# CQA Evidence

Прототип Conversation Quality Analytics для Freedom Broker CQA Hackathon.

**Статус: готов фронтенд и серверное подключение набора DEV. Автоматический оценщик и общий backend ещё не подключены.**
Исследование готовых решений выполнено до написания кода приложения, 7 ноября 2026.

Цель: оценивать новые RU/KZ/EN диалоги по редактируемому чек-листу, показывать проверяемые доказательства и сохранять историю апелляций. Главный приоритет — совпадение с оценками экспертов на неизвестных диалогах.

## Предлагаемый стек

React + TypeScript + Vite; Python FastAPI + Pydantic; SQLite; адаптер LLM; promptfoo для сравнения вариантов оценщика. Один сервер, один процесс обработки с ограниченной параллельностью, браузерный интерфейс. Фронтенд реализован на React + TypeScript + Vite. FastAPI, SQLite и LLM остаются задачами интеграции команды; модели не тестировались.

## Данные и запуск

Требуется Node.js 22+. В PowerShell:

```powershell
npm ci
Copy-Item .env.example .env.local
# Заполните ORGANIZER_DEV_URL в .env.local подписанной ссылкой из PDF заказчика.
npm run dev
```

Откройте http://127.0.0.1:5173. При первом запуске сервер получает все 65 диалогов DEV; повторные открытия используют локальную копию. Кнопка «Обновить DEV» запрашивает свежий набор. Без настроенной ссылки и локальной копии интерфейс покажет ошибку подключения.

```powershell
npm test
npm run build
npm run preview
```

Сборка работает через `npm run preview`, который также подключает серверный адаптер. Для размещения на общем сервере перенесите этот адаптер в backend: одна статическая папка `dist` не обслуживает API. Локальный адаптер предназначен для разработки, не для публичного размещения.

Фронтенд: обзор, поиск и фильтры диалогов, транскрипты и ссылки на аудио, официальный редактируемый чек-лист, интерфейс оценок и апелляций. Все 65 диалогов ожидают оценки: API заказчика не содержит экспертных баллов, а сервис оценщика ещё не подключён. Демо-диалоги и демо-оценщик удалены. Старое демонстрационное хранилище браузера удаляется при запуске.

API организаторов вызывается сервером. Подписанный URL задаётся локально через `ORGANIZER_DEV_URL`, ключ модели — через переменные окружения. Транскрипты, аудио, человеческая разметка и секреты не публикуются в Git. Файл `.env.local` и копия `local-data/organizer-DEV.json` исключены из Git. Не добавляйте к секретной переменной префикс `VITE_`.

DEV проверен через API: 65 диалогов, 60 чатов, 5 звонков; RU 35, KZ 15, EN 15. Эталонных оценок в полученных полях нет. Эти агрегаты описывают входные данные, а не качество будущего оценщика.

## Совместная работа

Три инженерных потока: AI/evaluation, backend/data/scoring, frontend/appeals. Пользователь — продуктовый эксперт и владелец демонстрации. Тимлид — архитектура, контракты, ревью, интеграция и контроль качества. Предварительные владельцы: Adalbala — AI, naki707 — backend, Krutoi312 — frontend. Подтверждено около 5 часов до сдачи; навыки участников пока неизвестны.

Работа через небольшие ветки и PR в `main`. До стоп-кода: воспроизводимый запуск, все обязательные сценарии, зафиксированный коммит и ссылка организаторам. Отправку ссылки выполняет команда.
