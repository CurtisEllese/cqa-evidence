# CQA Evidence

Команда: **Spooky spooky** · Data Challenge’26 · Freedom Broker.

Главный путь: «Диалоги» → выбрать сохранённый набор и версию чек-листа → «Оценить набор» → проверить проблемные результаты и доказательства → рассмотреть апелляцию. Пакетная очередь сохраняется в SQLite и продолжает работу на сервере после закрытия или обновления страницы. Можно остановить её после текущего диалога, продолжить только оставшиеся или отменить их без удаления истории. После перезапуска сервера продолжение требует явного действия; запрос с неизвестным результатом автоматически не повторяется и исключён из массовой переоценки. До явного запуска модель не вызывается. На одну SQLite запускается один backend worker; второй владелец базы блокируется. [Проверки очереди и границы гарантий](docs/audit/durable-batch-acceptance.md).

Конкурсная выгрузка вынесена из интерфейса заказчика: используйте `scripts/export_submission.py`. Служебная резервная копия доступна через `/api/export`. [Формат, проверка и сохранение результатов](docs/official-submission.md). [Пять синтетических персон и разговоров](docs/user-simulation.md). Презентация готовится отдельно.

Conversation Quality Analytics для Freedom Broker CQA Hackathon: React/TypeScript/Vite, FastAPI/Pydantic и SQLite.

Приложение работает с диалогами DEV и других групп организатора, версиями чек-листа, доказательствами и апелляциями. Активный API использует контракт **v2.0** и серверные задания оценки. Реальный оценщик требует подключения адаптера и провайдера; наличие API-ключа само по себе не создаёт оценки.

## Установка: Python 3.11 и Node.js 22+

Поддерживаемый Python — **3.11**. Проверенный локальный runtime — 3.11.18. Для нового окружения Windows PowerShell с установленным Python 3.11:

```powershell
py -3.11 -m venv .venv311
.venv311/Scripts/python.exe -m pip install -r backend/requirements.txt
npm ci
if (-not (Test-Path .env.local)) { Copy-Item .env.example .env.local }
```

Если Python устанавливается через уже доступный uv:

```powershell
uv python install 3.11
uv venv .venv311 --python 3.11
uv pip install --python .venv311/Scripts/python.exe -r backend/requirements.txt
npm ci
if (-not (Test-Path .env.local)) { Copy-Item .env.example .env.local }
```

Это альтернативные способы подготовки одного окружения; не создавайте его повторно поверх работающего. На Linux/macOS используйте `python3.11 -m venv .venv311` и путь `.venv311/bin/python`. В окружении, созданном uv без pip, устанавливайте зависимости через `uv pip`.

В `.env.local` укажите `ORGANIZER_DEV_URL` из материалов организаторов. Не публикуйте эту подписанную ссылку и ключи. Существующий файл конфигурации не заменяйте. `DATABASE_PATH` по умолчанию указывает на `local-data/cqa.sqlite`.

```powershell
npm run dev
```

Команда запускает UI на [127.0.0.1:5173](http://127.0.0.1:5173) и API на [127.0.0.1:8000](http://127.0.0.1:8000). Документация API: [127.0.0.1:8000/api/docs](http://127.0.0.1:8000/api/docs). После изменения Python или `.env.local` перезапустите процесс; Vite обновляет интерфейс автоматически. npm-обёртка предпочитает `.venv311` и проверяет Python 3.11.

Если порт занят, Vite может выбрать следующий. Фактический адрес UI должен быть в `APP_ORIGINS` на сервере, иначе кнопка загрузки вернёт «Источник запроса не разрешён». Для запуска на 5175 добавьте этот адрес к разрешённым в `.env.local` и перезапустите backend. [Настройка и проверка Origin](docs/control-datasets.md#ошибка-источник-запроса-не-разрешён).

## Проверки и готовая сборка

```powershell
.venv311/Scripts/python.exe scripts/generate_contracts.py --check
npm test
npm run build
npm start
```

`npm start` запускает FastAPI, который раздаёт `dist` и API по [одному локальному адресу](http://127.0.0.1:8000). Отдельные процессы: `npm run backend` и `npm run dev:ui`. Для `npm run preview` нужен backend на 8000.

После изменения Pydantic-моделей выполните генератор без `--check`, затем проверку и тесты. Сгенерированные файлы включайте в тот же PR. pytest/Hypothesis проверяют активный контракт, расчёт, задания, API/SQLite и аудио; тесты замороженного v1 сохраняются отдельно. Тестовые модели не подставляются в рабочие данные.

Дополнительная браузерная проверка: `.venv311/Scripts/python.exe tests/browser_smoke.py`. Для неё нужны Python Playwright и Chromium. Она использует отдельную базу в `tmp/qa`; проверки реального аудио зависят от доступности источника. Наличие ключа провайдера для обычных контрактных тестов не требуется.

## Подключение модели

Адаптер — асинхронная Python-функция внутри приложения:

```python
async def evaluate(request: EvaluationRequest) -> ModelResponse:
    ...
```

Для текущего OpenAI укажите `EVALUATOR_ADAPTER=evaluator.provider:evaluate`, `LLM_PROVIDER=openai`, `LLM_MODEL=gpt-6-luna` и серверный `OPENAI_API_KEY`; [инструкция подключения](docs/openai-evaluator.md). Без адаптера POST `/api/evaluations` возвращает 503. Настроенный контур возвращает 202 с ID задачи; её состояние читается через GET `/api/evaluations/{id}`.

Модель: **GPT-6 Luna**. В проверке 8 ноября обработаны **65/65 DEV** и шесть дополнительных синтетических запусков: всего **71 запрос без повторов**, 212 282 входных и 137 157 выходных токенов. Консервативная оценка общего расхода — **$0.09511375**, в среднем **$0.00134 за запрос**. Это измерение данного набора, а не обещание цены любого разговора; оно включает возможную повышенную стоимость cache writes и не является счётом OpenAI. Backend допускает до двух попыток, их расходы складываются; неизвестный usage не считается нулевым. [Отчёт прогона](docs/audit/jury-release-2026-11-08.json), [тариф и общий бюджет](docs/official-submission.md#модель-и-расходы).

Модель возвращает решения критериев и доказательства. Backend проверяет ссылки/цитаты, шкалы и N/A, рассчитывает итог и сохраняет результат. Непроверенные доказательства дают `needs_review` без итогового балла. В текущем продукте разрешена только OpenAI GPT-6 Luna, без переключения на другую модель. Ключ задаётся только на сервере. Рабочий лимит расходов — $0.50, включая повторные запросы; незавершённая попытка сохраняет резерв. Проверки подключения не заменяют экспертную проверку точности.

## Данные и сохранность

Для передачи модели проверенных продуктовых сведений можно настроить серверный
`KNOWLEDGE_FACTS_PATH`. Файл — утверждённый капитаном JSON-массив существующих
`KnowledgeFact`, не файл кандидатов из `docs/product`. Он проверяется при запуске
(до 1 МБ); некорректная настройка останавливает запуск с явной ошибкой. Без настройки
передаётся пустой список. После изменения файла нужен перезапуск; старые задачи
сохраняют первоначальные факты. Поле `checklistVersion` в запросе оценки выбирает
сохранённую версию; без него остаётся последняя. Примеры и границы проверки —
в [инструкции backend](docs/evaluation-context.md).

DEV: 60 чатов и 5 звонков; RU 35, KZ 15, EN 15. Эталонных оценок в API нет. Диалоги, версии чек-листа, исходные оценки, задания и решения апелляций сохраняются сервером в SQLite. В браузере остаются формы, поиск/фильтры и временный снимок состояния; окончательная арифметика выполняется сервером через Decimal.

Без `ORGANIZER_DEV_URL` приложение открывает пустую рабочую область для ручного импорта. Уже импортированные диалоги и оценки доступны после перезапуска без обращения к организатору. POST `/api/organizer/refresh` принимает `groupId` (по умолчанию DEV); имя группы и размер проверяются по ответу организатора, без требования «ровно 65». Новые группы добавляются к сохранённым данным. Коллизия ID с другим содержимым возвращает 409, сбой источника — 502; оба случая оставляют прежние данные и оценки. В окне «Загрузить диалоги» введите группу и нажмите «Загрузить набор»; ручной импорт JSON доступен ниже. [Контракт, состояния интерфейса и проверка](docs/control-datasets.md).

Источники звонков — HTML-плееры. Сервер извлекает файл и передаёт аудио с поддержкой перемотки; ссылки ручного импорта не загружаются сервером автоматически. Исходные оценки не переписываются апелляциями.

`.env.local`, `local-data`, `tmp`, аудио и скриншоты не должны попадать в Git. Для резервной копии остановите backend и скопируйте SQLite либо используйте SQLite Backup API; копирование только основного файла при активной WAL-записи недостаточно.

Запуск предназначен для localhost. Для общего размещения нужны авторизация, права на решения, HTTPS и резервное копирование. Ограничения Origin/localhost не заменяют авторизацию.
