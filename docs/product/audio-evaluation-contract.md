# Аудио при ограничении «только GPT-6 Luna»

Уточнённая цель пользователя — автоматическая оценка дикции/темпа/пауз/интонации без ручной операционной проверки каждого звонка. Описанный ниже helper по человеческим временным меткам эту цель **не закрывает**. Он отделяет допустимое измерение от вымышленной оценки; экспертная разметка остаётся необходимой для проверки точности будущей автоматизации. Варианты автоматизации исследуются отдельно в `automatic-voice-options.md`; ограничение Luna пока не отменено.

Проверено 8 ноября 2026 по [официальной карточке GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna): текст — input/output, изображение — input, **audio — Not supported**. Перечень общих API endpoints на той же странице не означает, что модель поддерживает каждый из них. [Официальное руководство Audio and voice](https://developers.openai.com/api/docs/guides/audio) отделяет транскрипцию, голосовые модели и текстовые агенты. В продукт не добавлена другая модель и не выполнен ни один платный запрос.

## Реализованная часть

`evaluator.audio_metrics.inspect_pcm_wav(path)` работает локально на PCM WAV 16-bit, mono/stereo, 8–96 kHz, до 64 MiB и 30 минут. Возвращает hash исходных байтов, длительность, частоту, по каждому каналу RMS dBFS, пик, долю отсчётов на полном масштабе и долю/длительность тихих окон. Порог по умолчанию −40 dBFS, окно 20 ms, оба явно записываются в результат. Каналы не усредняются, чтобы противоположная фаза не превращала голос в «тишину». Финальное неполное окно учитывается по длительности.

Это **измерения сигнала**, не оценка дикции, пауз речи, громкости голоса оператора или качества обслуживания. Музыка/шум могут быть громкими, речь тихой; энергетический порог не является детектором речи. Полный масштаб означает возможный clipping, но не доказанное искажение. На тишине dBFS — null и `silent=true`, без бесконечностей в JSON. Никаких порогов штрафов или фиктивных оценок.

`measured_tempo(audio_sha256, duration_seconds, segments, reviewer, language)` рассчитывает слова/минуту только по проверенным человеком интервалам **оператора** и количеству слов в этих интервалах. Каждый segment содержит `audioSha256`, `startSeconds`, `endSeconds`, `wordCount`, `speaker=operator`, `verified=true`. Интервалы должны соответствовать записи, быть упорядоченными, непересекающимися и находиться в её пределах. Обязательны псевдоним проверяющего и RU/KZ/EN. Пустой список возвращает `not_assessed`.

Длительность включает паузы внутри размеченного хода. Это темп по ходам, не articulation rate и не показатель дикции. Критерий разбиения слов должен быть согласован отдельно для RU/KZ/EN; автоматического сравнения языков с общей «нормой» нет. Текст без аудиопривязки и проверенных интервалов не допускается. Число слов передаёт человек: существующая транскрипция сама по себе не подтверждает полноту/ошибки ASR или правильность говорящего.

## Контракт будущей интеграции

Владелец backend может вызывать модуль после разрешённого получения локального файла и проверки формата. Он должен проверить hash, сопоставление файла разговору, права доступа и подтверждение разметчика; эти свойства не доказываются флагом `verified=true`. Сейчас модуль не подключён к API, UI и checklist scoring, не загружает URL и не читает рабочее хранилище.

Для надёжной оценки дикции нужны исходное аудио, точные границы оператора, утверждённая рубрика произношения/разборчивости для нужного языка и независимые человеческие оценки. Без другого разрешённого audio-моделя можно реализовать полностью человеческую проверку. Локальное ASR/VAD можно отдельно исследовать после решения владельца о модели, лицензии, ресурсах и валидации на KZ/RU/EN, но это будет **другая модель**, пусть и без платного API; текущая задача не даёт основания незаметно добавить её.

При текущих ограничениях автоматическая оценка дикции/интонации блокирована возможностями Luna. Поля `diction.score`, `intonation.score`, `voiceQualityScore`, `qualityScore` остаются null. Метрики тишины, темпа и частотного спектра не заменяют этот пробел.
