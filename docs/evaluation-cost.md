# Модель и примерная стоимость оценки

Текущая конфигурация: OpenAI Responses API, `gpt-6-luna`. Для оценки передаётся
текст транскрипта и чек-лист; аудио модель не анализирует.

Тариф проверен 7 ноября 2026 по официальной документации
[GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna) и
[Pricing](https://developers.openai.com/api/docs/pricing): Standard, до 272 000
входных токенов, **$0.10 за миллион входных** и **$0.50 за миллион выходных**.
Ниже расчёт без скидки за кеш, платных записей кеша, других режимов и региональных
надбавок. Это оценка по тарифу, не подтверждённое списание. При смене модели,
режима или цены расчёт нужно обновить.

## Измеренная основа

Источник токенов — сохранённый [живой синтетический прогон](audit/openai-luna-smoke.json),
а не новый запрос при подготовке документа. В отчёте три случая и три попытки:
по одному вызову на оценку, повторов в этом прогоне не было.

| Случай | Входные токены | Выходные токены | Оценка стоимости, USD |
|---|---:|---:|---:|
| RU, чат | 2267 | 892 | 0.0006727 |
| KZ, транскрипт звонка | 2345 | 1021 | 0.0007450 |
| EN, чат | 2253 | 932 | 0.0006913 |
| Всего | 6865 | 2845 | 0.0021090 |

Среднее на этих трёх коротких примерах — **$0.000703 за оценку**. Это не измеренная
средняя стоимость DEV или контрольной группы и не проверка экспертной точности.

## Учёт всех вызовов

Стоимость оценки = сумма по всем попыткам:
`(input_tokens × 0.10 + output_tokens × 0.50) / 1 000 000`.

Backend допускает максимум две попытки, включая исправление ответа. Адаптер делает
один HTTP-запрос за попытку, без скрытого retry или автоматического Gemini fallback.
Если обе попытки стоили как средний вызов выше, оценка обошлась бы примерно в
**$0.001406**. Это иллюстрация, не потолок: повтор содержит feedback, а длина ответа
может меняться. Апелляцию и пересчёт баллов выполняет backend без нового вызова LLM.

В `local-data/openai-usage.jsonl` учитывайте все попытки, включая неудачные ответы
с известным usage. `null` в токенах означает неизвестный расход, не бесплатный вызов;
при таких строках полный итог стоимости неизвестен. Текущий журнал не содержит ID
задания, поэтому по смешанному журналу нельзя надёжно восстановить цену отдельной
повторно запущенной оценки. `cost_usd` в журнале остаётся `null`: тарифная оценка
из этого документа не подменяет данные провайдера.

Пересчитать опубликованный пример из корня репозитория без сети и ключа:

```python
import json
from decimal import Decimal
from pathlib import Path

report = json.loads(Path("docs/audit/openai-luna-smoke.json").read_text())
amounts = []
for attempt in report["attempts"]:  # Все попытки, без фильтра по outcome.
    incoming, outgoing = attempt["input_tokens"], attempt["output_tokens"]
    if attempt["model"] != "gpt-6-luna" or incoming is None or outgoing is None:
        raise ValueError("Нужен известный usage и тариф выбранной модели")
    if incoming > 272_000:
        raise ValueError("Нужен тариф длинного контекста")
    amounts.append((Decimal(incoming) * Decimal("0.10")
                    + Decimal(outgoing) * Decimal("0.50")) / Decimal(1_000_000))
total = sum(amounts, Decimal(0))
print("USD за все попытки:", total)
print("USD на случай:", total / len(report["cases"]))
```

Фактические списания и неизвестный usage сверяются с биллингом владельца API-проекта.
