# Сверка с выданным ТЗ

Основание: четыре страницы задания CQA и три страницы чек-листа, переданные
Дильназ 7 ноября 2026. Презентация «Data 2» содержит контекст Freedom, а не схему
результатов или продуктовые правила для критерия консультации.

## Что нужно сдавать

В переданных страницах указаны открытый Git-репозиторий, понятный README,
фиксация коммита к стоп-коду и демонстрация до пяти минут. Требования к файлу
`results.json`, его полям или номерам критериев в экспорте здесь нет.
Существующий экспорт приложения доступен, но не объявляется отдельным официальным
форматом. Если организаторы передадут приложение с такой схемой, его проверим отдельно.

Точное время стоп-кода и канал сдачи нужно подтвердить по расписанию. Необходимо
подтверждение, что организаторы получили ссылку на репозиторий; публикация PR сама
по себе не означает отправку ссылки организаторам.

## Что исправлено после сверки

- PR #11 объединён в main: загрузка групп, сохранность данных, выбор версии,
  фильтр исходных грубых ошибок и переход к доказательству. Коммиты #9/#10 входят в него.
- В начальном `backend/rubric.json` исправлена принадлежность критериев к секциям.
  Раньше эмпатия и управление диалогом входили в «Работу с запросом», завершение
  стояло отдельно. Общий балл не менялся, но итоги секций не соответствовали PDF.
- Из начального №3 убрано самостоятельное условие о согласии на обработку данных:
  это не отдельная формулировка PDF. Требование подтверждённой проверки личности сохранено.
- В README добавлены модель и [примерная стоимость](evaluation-cost.md),
  включая правило суммирования повторных вызовов. Исправлено устаревшее заявление,
  что подключение модели ещё не реализовано.

Тесты проверяют реальные API-итоги секций для примера 85.38, изменение только
нужной секции после апелляции и сохранение старой версии/оценок при обновлении seed.

Проверено на Linux, Python 3.11.17: 424 Python-теста, 9 JS-тестов,
32 артефакта контрактов и production build прошли. В Chromium проверены карточка
и редактор с новыми названиями секций на 1440/375 px: без переполнения и ошибок JS.
Этот браузерный проход использовал синтетический диалог и реальные ответы локального
API с тестовой оценкой, без вызова платной модели.

## Если база уже создана

Обновление файла начальной конфигурации **не переписывает SQLite и старые оценки**.
В существующей базе откройте редактор чек-листа, установите секции по таблице,
приведите описание №3 к правилу PDF и сохраните новую версию. Выберите её для новых
оценок. Нельзя удалять рабочую базу ради обновления начальной конфигурации.

| Секция | Критерии |
|---|---|
| Начало и понимание запроса | 01, 02 |
| Безопасность и решение | 03, 04 |
| Ведение и завершение диалога | 05, 06, 07 |
| Грубые нарушения | 08 |

Описание №3: «Проверка личности подтверждена до раскрытия данных или защищённого
действия. Если обязательная проверка не подтверждена в чате, ответ — Нет».
Старые результаты продолжают ссылаться на свою версию. Отдельного разрешения на
переписывание старых версий это изменение не даёт.

## Оставшаяся приёмка

| Проверка | Что считать подтверждением |
|---|---|
| Живой сценарий на объединённой версии | Новый диалог → модель → доказательство → апелляция → перезапуск → сохранённый результат. Предыдущий live-аудит относится к версии до интеграции. |
| Изменение критерия | Новая формулировка и шкала сохранены через UI; модель использует новые значения, старый результат остаётся на своей версии. |
| Точность RU/KZ/EN | Независимая ручная разметка, разбор расхождений и N/A/№8. Синтетические smoke-тесты не заменяют её. |
| Контрольная группа | Фактический group_id от организаторов, все выданные записи обработаны; сбой импорта сохраняет старые данные. Размер не зашит. |
| Защита | Прогон до пяти минут и резервная запись; подтверждённый SHA перед стоп-кодом. |

В этом рабочем цикле новых запросов к платной модели не выполняли. Проверка
доступности ключа/квоты и живая демонстрация нужны на компьютере команды.
Плейер и транскрипт доступны, но анализ дикции и интонации не заявляется.
Политика текущей версии запрещает переоценку диалога с историей апелляций; для
демонстрации нового критерия используйте новый диалог и явно покажите выбранную версию.

Не начинаем новую архитектуру ради защиты. По этому ТЗ React допустим, отдельный
Web Component и регистрация не обязательны. Нормирование секций и HALF_UP —
явные [соглашения реализации](requirements.md), а не дословные правила PDF.
