# Контрольные наборы: backend P0 / задача #2

Backend принимает выбранный `groupId`, передаёт его организатору как `group_id`,
проверяет весь набор и сохраняет его одной транзакцией. Оценки, апелляции и ручные
диалоги остаются доступны после загрузки другой группы и перезапуска.
Расчёт, Gemini-адаптер и лимит двух provider-попыток не изменены.

## Передача Krutoi312

- Контракт: `backend/contracts/v2/models.py`, `RefreshRequest.groupId`.
- Сгенерированные типы: `src/generated/contracts.ts`; схема: `contracts/v2/RefreshRequest.schema.json`.
- `POST /api/organizer/refresh` → `WorkspaceState`; примеры и ошибки описаны в [contracts-v2.md](contracts-v2.md).
- Без `groupId` остаётся DEV. Поле — непустая строка до 512 символов после trim.
- `dataset` описывает последний загруженный набор, `data.conversations` — все сохранённые активные диалоги. Для текущей группы использовать `dataset.conversationIds`, а не длину общего списка.
- Ошибка не должна очищать список. Группу остальных/ручных записей не угадывать.
- Backend готов к подключению поля. Реальный UI-сценарий принимает Krutoi312 вместе с Roman после интеграции; наличие контракта не означает, что поле уже работает в интерфейсе.

## Проверка за две минуты

Установка и настройка серверного `ORGANIZER_DEV_URL` — по README.
После `npm run build` запустить `npm start`. DEV доступен старому клиенту:

```sh
curl -sS http://127.0.0.1:8000/api/organizer/refresh -H 'Content-Type: application/json' -d '{"schema_version":"2.0"}'
```

Подставить **выданный организатором** идентификатор вместо `CONTROL_EXAMPLE`:

```sh
curl -sS http://127.0.0.1:8000/api/organizer/refresh -H 'Content-Type: application/json' -d '{"schema_version":"2.0","groupId":"CONTROL_EXAMPLE"}'
curl -sS http://127.0.0.1:8000/api/export -o control-workspace.json
```

Проверить `dataset.group`, `total` и `conversationIds`. Для одного ID из ответа:

```sh
curl -sS http://127.0.0.1:8000/api/evaluations -H 'Content-Type: application/json' -d '{"schema_version":"2.0","conversationId":"ACTUAL_CONVERSATION_ID"}'
curl -sS http://127.0.0.1:8000/api/evaluations/ACTUAL_JOB_ID
```

ID диалога и задачи в примерах — placeholders, их нужно заменить. Оценка требует
настоящего подключённого адаптера/ключа; без него ожидается 503. Импорт не запускает
массовую оценку автоматически. Путь импорта JSON остаётся резервом: POST `/api/import`
с `schema_version` и `text`, содержащим полный JSON-ответ либо массив записей.
После перезапуска с тем же `DATABASE_PATH` прежний результат должен читаться без
нового вызова модели. Экспорт содержит все сохранённые группы; формат сдачи и нужный
вид результата подтверждает капитан, это не обещание совместимости с форматом жюри.

Без ключа/сети проверяются синтетические наборы и тестовый адаптер:

```sh
npm run contracts:check
npm test
npm run build
```

Адресная проверка: `.venv/bin/python -m pytest backend/tests/test_control_datasets.py -q`
(для Windows заменить Python на `.venv311/Scripts/python.exe`).
Тесты охватывают DEV 65, CONTROL 10, другой размер, пустой набор, все 10 оценок и
экспорт, повтор, коллизии, повреждённую запись, сбои сети, перезапуск и аудио.
Это не вызовы Gemini и не проверка смысловой точности.

## Хранение и решения

- В текущей SQLite-схеме не нужна разрушающая миграция. `metadata.dataset` хранит
  текущий набор, `metadata["dataset:" + groupId]` — последний снимок состава каждой
  загруженной группы. При первом обновлении сохраняются и прежние DEV-метаданные.
- Источник новых записей — `organizer:<groupId>`. Старое значение `DEV` остаётся
  совместимым. Существующая запись сохраняет первоначальный источник, в том числе
  `manual`, даже если тот же ID встретился у организатора. Набор может содержать ID
  из другой группы; членство хранится отдельно в метаданных набора.
- Одинаковый ID и то же нормализованное содержимое не создают копий; новая загрузка
  обновляет метаданные загрузки, но не вызывает модель и не меняет оценки.
- Одинаковый ID с другим содержимым, включая язык, аудиоссылку или текст, даёт 409
  **до записи**. Это выбранная политика этого PR. Даже обновлённая подписанная
  аудиоссылка требует явного решения по обновлению, а не тихого переписывания.
- Уменьшившийся состав группы не удаляет старые записи. Результаты и апелляции
  остаются привязаны к исходным ID/снимкам.
- Ошибки группы/total/записи/повторяющегося ID дают 502. `total_records` должен быть
  целым числом, равным длине массива; bool, float и строка не принимаются.
- Пустой успешный набор с total=0 допустим как решение реализации: он обновляет
  метаданные и сохраняет старые диалоги. Это не утверждение о контрольном наборе.
  Существующие ограничения 5 МБ / 1000 записей остаются в силе.
- URL организатора берётся только с сервера; client URL не принимается. Аудио
  новых групп использует прежнюю проверку источника и Range-прокси. Ручной импорт
  не получает доверие для серверного аудиопрокси.
