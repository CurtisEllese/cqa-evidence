# Контрольные наборы: backend P0 / задача #2

Backend принимает выбранный `groupId`, передаёт его организатору как `group_id`,
проверяет весь набор и сохраняет его одной транзакцией. Оценки, апелляции и ручные
диалоги остаются доступны после загрузки другой группы и перезапуска.
Расчёт, Gemini-адаптер и лимит двух provider-попыток не изменены.

## Загрузка через интерфейс и состояния

На страницах «Обзор», «Диалоги» и в окне «Загрузить диалоги» показан последний успешно загруженный набор. Группа берётся из `dataset.group`, число записей — из `dataset.total`, время — из `dataset.fetchedAt`. Общее количество сохранённых диалогов берётся отдельно из `data.conversations.length`: оно может быть больше размера последнего набора.

- До ответа сервера введённое значение не меняет название и количество последнего набора.
- Во время запроса кнопка показывает «Загружаем набор…», рядом появляется «Загружаем группу …». Поле, загрузка файлов и повторное нажатие заблокированы.
- После успешного ответа обновляются данные и появляется «Набор загружен». Набор из нуля записей показывается как 0, а не как отсутствие данных.
- При ошибке сообщение показано рядом с полем группы; предыдущие диалоги, оценки и метаданные набора остаются. Можно исправить идентификатор и повторить запрос.
- Если `dataset` отсутствует, но диалоги есть, показано «Группа набора не указана». При пустой рабочей области — «Набор не загружен». Происхождение ручных записей не выводится из значения поля.
- Ручной импорт JSON остаётся ниже. Загрузка набора не запускает оценку ИИ автоматически.

## Ошибка «Источник запроса не разрешён»

Сервер проверяет заголовок `Origin` по списку `APP_ORIGINS`. Схема, имя хоста и порт должны совпадать: `http://127.0.0.1:5175` и `http://localhost:5175` — разные источники. В стандартном списке есть порты 5173, 4173 и 8000, но нет 5175.

При локальной проверке 7 ноября 2026 года UI работал на 5175. Запрос из командной строки без `Origin` успешно загрузил DEV, но нажатие кнопки в браузере получало HTTP 403 / `ORIGIN_FORBIDDEN`. Причина — адрес UI отсутствовал в разрешённом списке; это не ошибка идентификатора DEV или API организаторов.

Для такого запуска задайте в `.env.local` следующий список. Если у вас уже есть дополнительные разрешённые адреса, сохраните их и добавьте нужные значения; остальные настройки файла не заменяйте.

```dotenv
APP_ORIGINS=http://127.0.0.1:5173,http://localhost:5173,http://127.0.0.1:4173,http://localhost:4173,http://127.0.0.1:8000,http://localhost:8000,http://127.0.0.1:5175,http://localhost:5175
```

Адреса разделяются запятыми без пробелов и завершающего `/`. После изменения перезапустите **backend**, затем обновите страницу. Подписанную ссылку `ORGANIZER_DEV_URL` и ключи в документацию не переносите. Проверку Origin не отключайте.

Проверка на Windows (на Linux/macOS используйте `curl` вместо `curl.exe`):

```powershell
curl.exe -i -H "Origin: http://127.0.0.1:5175" http://127.0.0.1:5175/api/health
curl.exe -i -H "Origin: https://unrelated.example" http://127.0.0.1:5175/api/health
```

Первый запрос должен вернуть 200, второй — 403. Затем откройте UI на том же адресе и нажмите «Загрузить набор» для DEV. Проверка только через curl без `Origin` не подтверждает работу браузерной кнопки.

После исправления выполнена реальная загрузка DEV нажатием кнопки в Chromium: HTTP 200, `dataset.group=DEV`, `dataset.total=65`, `dataset.source=live`, сообщение об успехе видно. Отдельное сравнение состояния до и после загрузки подтвердило сохранность прежних диалогов и апелляций. Настоящая контрольная группа пока не проверена.

Проверка состояний UI на синтетических ответах без изменения рабочей базы (нужны Python Playwright, Chromium и запущенный UI):

```powershell
python tests/browser_dataset_ui.py --url http://127.0.0.1:5175/
```

Она проверяет название и количество, загрузку, ошибку без потери списка, пустой набор, блокировку повторов, ручной JSON и узкий экран. Она не заменяет реальный вызов организаторов из браузера.

### Ручная проверка сбоя и восстановления через сервер

7 ноября 2026 года в `codex/dataset-group-ui` выполнен сценарий через видимый браузер и отдельный процесс настоящего FastAPI на `http://127.0.0.1:8001`. Использована отдельная SQLite-база `tmp/manual-dataset-check-01/qa.sqlite`. Источник — локальный HTTPS-имитатор организатора с проверяемым тестовым сертификатом; браузерные ответы не подменялись. Оценка для проверки сохранности подготовлена тестовым адаптером, без вызова Gemini.

1. Исходное состояние: группа BASE из 2 записей, 1 ручной диалог, оценка BASE-0 **85.38** и 1 апелляция на рассмотрении.
2. В окне загрузки введён CONTROL и выполнено двойное нажатие. Пока источник задерживал ответ, поле и кнопки были заблокированы. Источник вернул 500, приложение — 502 / `UPSTREAM_ERROR`. На одно двойное нажатие пришёл ровно один запрос.
3. После ошибки весь ответ `/api/state` совпал с исходным, включая revision, транскрипты, оценку, апелляцию и метаданные группы. На экране оставались 3 диалога и прежняя оценка.
4. Обнаружена и исправлена ошибка общей кнопки «Повторить загрузку»: раньше после сбоя набора она только перечитывала `/api/state`. Теперь повторяет POST для последней неудачной группы; при ошибке начального чтения состояния по-прежнему повторяет загрузку рабочего пространства.
5. После повторной проверки сбоя источник переключён на успешный ответ. Двойное нажатие общей кнопки повтора отправило один запрос CONTROL и получило 200. Показаны 10 записей набора и 13 сохранённых диалогов всего.
6. Прежние 3 диалога, оценка **85.38** и апелляция не изменились. Это проверено сравнением данных, открытием карточки и истории апелляций, затем обновлением страницы. Число задач оценки осталось 1: загрузка не запустила новые оценки.

За два запуска сценария сбоя и один успешный повтор журнал содержит ровно три запроса: `502, 502, 200`. Контрольный отпечаток экспорта рабочего сервера на 8000 до и после проверки совпал. Рабочая база не изменялась. Отчёты сравнения и снимок ошибки оставлены в `tmp/manual-dataset-check-01/`; они не включаются в Git. Это проверка управляемого сбоя источника через настоящий сервер приложения, а не заявление о сбое или восстановлении внешнего API организаторов.

## Проверка ручного JSON-импорта 7 ноября 2026 года

Проверен настоящий процесс FastAPI на порту 8002 с отдельной базой `tmp/json-import-check-01/qa.sqlite`, без `ORGANIZER_DEV_URL` и без кеша DEV. Подготовлены синтетическая оценка **85.38** и апелляция для проверки сохранности; Gemini не вызывался.

- **Оба формата:** массив записей и объект `isSuccess: true` / `data.records` принимаются сервером. В браузере каждый формат проверен и выбором файла, и вставкой текста; добавлено по одной записи каждым из четырёх способов.
- **Ошибки:** неверный JSON, неправильная структура, пустой массив, `isSuccess: false`, некорректная запись среди корректных и более 1000 записей возвращают 422 без частичного сохранения.
- **Дубли:** повтор уже импортированного набора возвращает 422 с понятным сообщением; одинаковые записи внутри одного файла дают одну новую запись; смесь существующей и новой добавляет только новую. Конфликт существующего ID с другим содержимым возвращает 409; соседняя новая запись также не сохраняется.
- **Сохранность:** при каждом отказе весь ответ `/api/state` совпадает с состоянием до запроса. Успешные импорты сохраняют предыдущие диалоги, оценку и апелляцию. Ручной импорт не приписывает записям группу организаторов: `dataset` остаётся `null`.
- **Перезапуск:** процесс остановлен и заново запущен с той же базой и без ссылки организаторов. Все 12 диалогов, оценка **85.38**, апелляция, revision и остальное состояние полностью совпали. Карточка и история апелляций дополнительно проверены в браузере после перезагрузки страницы.
- **Изоляция и завершение:** контрольный отпечаток экспорта рабочего сервера не изменился. Тестовый сервер после проверки остановлен, порт 8002 освобождён, тестовая вкладка закрыта. Синтетические отчёты и снимок сохранены в `tmp/json-import-check-01/`, вне Git.

**Лимит 5 МБ исправлен и проверен.** Ранее сервер сравнивал с пределом размер всего запроса, включая обёртку и экранирование, поэтому исходный файл ровно на 5 МиБ отклонялся. Теперь `/api/import` проверяет размер исходного JSON в UTF-8: до **5 242 880 байт включительно**. Превышение возвращает 413 до сохранения записей. Отдельный предел транспортного запроса — `6 × 5 242 880 + 1024` байт: он учитывает максимальное расширение при JSON-экранировании. Для остальных маршрутов предел запроса не изменён.

Повторная проверка выполнена через настоящий сервер на порту 8002 с отдельной базой `tmp/json-size-fix-01/qa.sqlite`, без источника организаторов и кеша:

- Массив записей и ответ организаторов ровно на 5 242 880 байт приняты через HTTP и через выбор файла в браузере; сохранены четыре тестовые записи.
- Оба формата на один байт больше получили 413 без изменения состояния. Браузер отклонил превышение при выборе файла, показал «Размер файла не должен превышать 5 МБ» и оставил кнопку отправки недоступной.
- Добавлены семь граничных серверных тестов: UTF-8 с кириллицей, экранирование, максимальное расширение транспортного JSON, превышение при обычной и потоковой передаче, сохранение лимита остальных маршрутов. Полный прогон: 367 серверных и 7 клиентских тестов прошли; сборка и проверка контрактов также прошли.
- Экспорт рабочей базы до и после совпал. Тестовый сайт остановлен, порт 8002 освобождён, вкладка закрыта. Файлы и снимок проверки находятся в `tmp/json-size-fix-01/`, вне Git.

## Хранение и решения

- В текущей SQLite-схеме не нужна разрушающая миграция. `metadata.dataset` хранит
  текущий набор, `metadata["dataset:" + groupId]` — последний снимок состава каждой
  загруженной группы. При первом обновлении сохраняются и прежние DEV-метаданные.
- Источник новых записей — `organizer:<groupId>`. Старое значение `DEV` остаётся
  совместимым. Существующая запись сохраняет первоначальный источник, в том числе
  `manual`, даже если тот же ID встретился у организатора. Набор может содержать ID
  из другой группы; членство хранится отдельно в метаданных набора.
- Одинаковый ID и то же нормализованное содержимое не создают копий; новая загрузка
  обновляет метаданные загрузки, но не вызывает модель и не меняет оценки.
- Одинаковый ID с другим содержимым, включая язык, аудиоссылку или текст, даёт 409
  **до записи**. Это выбранная политика этого PR. Даже обновлённая подписанная
  аудиоссылка требует явного решения по обновлению, а не тихого переписывания.
- Уменьшившийся состав группы не удаляет старые записи. Результаты и апелляции
  остаются привязаны к исходным ID/снимкам.
- Ошибки группы/total/записи/повторяющегося ID дают 502. `total_records` должен быть
  целым числом, равным длине массива; bool, float и строка не принимаются.
- Пустой успешный набор с total=0 допустим как решение реализации: он обновляет
  метаданные и сохраняет старые диалоги. Это не утверждение о контрольном наборе.
  Существующие ограничения 5 МБ / 1000 записей остаются в силе.
- URL организатора берётся только с сервера; client URL не принимается. Аудио
  новых групп использует прежнюю проверку источника и Range-прокси. Ручной импорт
  не получает доверие для серверного аудиопрокси.
