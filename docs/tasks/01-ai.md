**Переход провайдера:** капитан выбрал OpenAI API. Общая точка входа `evaluator.provider:evaluate`, OpenAI — `evaluator/openai_v2.py`, общий промпт — `evaluator/prompt.py`. Работать с текущим провайдером; исторические Gemini-результаты не выдавать за OpenAI. [Подключение и проверки](../openai-evaluator.md).

**Обновление Freedom:** [официальные уточнения](../organizer-clarifications.md) имеют приоритет: живой продукт и разумные обоснования; не оптимизируемся под неизвестную формулу. Для калибровки сначала короткий проход 30–45 минут.


Приоритет: **P0**. Задача: [#1](https://github.com/CurtisEllese/cqa-evidence/issues/1). База — актуальный main с OpenAI; исторический аудит выполнен на `2939747` с Gemini. Рабочая ветка: `fix/evaluator-semantics`. Сначала принять уже выданное GitHub-приглашение.

## Цель и границы

Модель должна применять смысл переданного критерия без дополнительных требований. OpenAI Responses API, адаптер `evaluator.provider:evaluate` с моделью `gpt-6-luna`, структурированный ответ, серверный расчёт и общий лимит двух попыток уже реализованы. Их повторно не писать. Владелец файлов `evaluator/*`, связанных тестов и инструмента измерения качества — Adalbala. Серверный контракт меняет Дильназ, UI — Krutoi312.

## P0.1. Исправить воспроизводимую ошибку

- [ ] Воспроизвести [пример аудита](../audit/custom-criterion-repro.json). Правило: 5 — даны шаги и клиент подтвердил решение; 2 — шаги без подтверждения; 0 — шагов нет. В историческом аудите Gemini вернула 2 вместо 5, добавив требование о запросе подтверждения оператором.
- [ ] Сделать три минимальных варианта: шаги + подтверждение → `5`; шаги без подтверждения → `2`; нет шагов → `0`. Менять только проверяемое условие; сохранять исходные роли и порядок.
- [ ] Исправить общий способ применения критериев: выбирать значение по явно указанным условиям, искать подтверждение/опровержение в сообщениях, не добавлять отраслевые «лучшие практики». Конкретный ID, название или текст теста не могут определять ответ в коде.
- [ ] Обновить версию промпта. Не запрашивать скрытые рассуждения: достаточно краткого проверяемого объяснения и источников.
- [ ] Проверить ещё минимум три незнакомых формулировки/шкалы, включая yes_no, scale и разрешённый N/A. Сохранить результаты отдельно от обучающих примеров.

**Приёмка:** три варианта дают 5/2/0; объяснения не содержат дополнительных условий; новые критерии применяются без ручного изменения кода/промпта под каждый критерий; исходный официальный чек-лист не регрессирует. Не объявлять успех по одному удачному повтору: сравнить минимум два запуска проблемной тройки без кэша, указать расхождения и число вызовов.

## P0.2. Измерить точность

- [ ] Вместе с капитаном и Roman подготовить 12–15 размеченных DEV-примеров RU/KZ/EN: N/A, отсутствие действий, частичный ответ, №8, звонки. Эталон сначала размечается людьми без просмотра ответа модели.
- [ ] Roman хранит отдельную проверочную часть; похожие сценарии/переводы находятся в одной части. Промпт настраивается только на части для разработки.
- [ ] Сделать команду сравнения: вход — диалоги и ручные решения; выход — JSON/таблица ошибок и агрегаты. Итог эталона и модели считать существующим серверным расчётом, без второй формулы в evaluator.
- [ ] Выводить exact match по каждому критерию, ошибки N/A, MAE итогового балла, №8 отдельно, срезы языка/канала и размер каждой группы. Failed/needs_review считать отдельным покрытием, не молча исключать из знаменателей качества.
- [ ] Финальный прогон закрытой части выполняет Roman после фиксации промпта. Если по ней снова настраиваем — явно перестаёт быть независимой проверкой.

**Приёмка:** есть воспроизводимая команда, файл результатов, количество валидных/ошибочных/неподтверждённых оценок, таблица до/после. Отчёт не называет командную разметку официальным Ground Truth и не обещает 100% точность.

## Ограничения и передача

Без второго провайдера, обучения собственной LLM, обязательного второго прохода или новых микросервисов. Не менять message_id. Ошибки API/JSON не превращать в успешный ответ. Не добавлять скрытые SDK-повторы сверх серверного лимита. Синтетические заглушки допустимы только в tests.

Первый PR — воспроизведение + общее исправление + регрессии; метрики не откладывать до окончания всех функций. Перед передачей: `npm test`, `npm run contracts:check`, `npm run build` для общего состояния; живые вызовы отдельно, явно включаемой командой. В PR написать: что было неверно, что изменено, какие примеры прошли/не прошли, число вызовов и ограничения. Ключи, реальные записи и ручная разметка клиентов не попадают в публичный Git.
