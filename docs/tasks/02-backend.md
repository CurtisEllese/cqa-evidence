## Цель и границы

Получить контрольный набор по новому group_id и обработать его без изменения кода после стоп-кода. Backend v2, SQLite, расчёт, задания, апелляции и Gemini уже объединены. Не переписывать их. Дильназ владеет `backend/*`, Pydantic-моделями, генератором контрактов, связанными тестами и изменениями API-документации. Промпт остаётся у Adalbala.

## P0.1. Контракт для UI — первая передача

Целевое совместимое расширение, **ещё не существующее в проверенном main**:

```http
POST /api/organizer/refresh
Content-Type: application/json

{"schema_version":"2.0","groupId":"<значение организаторов>"}
```

`groupId` — непустая строка, пробелы по краям удаляются, разумный лимит длины; не ограничивать неизвестный формат группы догадками. Если поле отсутствует, оставить DEV для совместимости старого клиента. В upstream GET передавать именно `group_id`. Секретная подписанная базовая ссылка берётся из существующего серверного ORGANIZER_DEV_URL, в браузер не передаётся. Ответ остаётся WorkspaceState v2; dataset.group/total/conversationIds отражают загруженную группу.

- [ ] Не редактировать generated вручную. Не менять Decimal-строки, yes_no, ID или форматы ошибок ради этой задачи.

## P0.2. Получение и сохранность набора

- [ ] Убрать принудительный DEV в upstream-запросе и проверку «всегда ровно 65» для всех групп. Проверять isSuccess, совпадение запрошенной и возвращённой группы, total_records и валидность records. Не захардкодить вместо 65 новое число 10.
- [ ] Проверять весь ответ до изменения SQLite. Ошибка API, таймаут, неправильный total/group или одна плохая запись сохраняют прежний набор и оценки.
- [ ] Сохранить происхождение записей и историю результатов. Повторный импорт тех же ID/содержимого не создаёт дубликаты и не запускает модель автоматически.
- [ ] Определить политику коллизий явно: одинаковый ID с другим содержимым не перезаписывается незаметно; для этого этапа допустим понятный 409 без изменения базы. Не переименовывать исходные ID молча. При необходимости более сложного обновления согласовать отдельно и сохранить снимки старых оценок.
- [ ] Старые записи/оценки должны оставаться доступны после загрузки новой группы и после перезапуска; глобальный refresh не должен очищать manual-импорты.
- [ ] Не загружать произвольный переданный пользователем URL. Аудио новых групп должно пользоваться теми же ограничениями доверенного источника, что и DEV; ручной импорт не получает доверие автоматически.

**Приёмка:** фиктивный upstream возвращает DEV 65 и CONTROL 10; оба импортируются, метаданные корректны; дополнительно набор другого размера доказывает отсутствие хардкода. Проверить неверную группу/total, дубль, коллизию ID, сетевую ошибку, сохранность оценки/апелляции и перезапуск. Вызов нового groupId проходит через UI после интеграции Krutoi312. Настоящую контрольную группу до её выдачи не угадывать.

**Резерв до исправления:** получить ответ организатора отдельно и импортировать JSON через существующий /api/import. Roman должен проверить этот путь на наборе из 10 синтетических записей.

- [ ] Подключить локальный серверный JSON по новой документированной переменной KNOWLEDGE_FACTS_PATH. Это планируемая настройка, сейчас её нет. Использовать существующий KnowledgeFact: text, source, effective_date, product, jurisdiction, verified_by.

- [ ] Снимок применимых фактов сохранять вместе с EvaluationRequest; смена файла не меняет уже начатую/сохранённую оценку. Никакой отдельной векторной БД на этом этапе.

**Приёмка:** тест показывает фактическое попадание проверенных данных в адаптер и неизменность снимка. Содержание и применимость предоставляет капитан; backend не изобретает правила Freedom.

## P1.2. Выбор сохранённой версии чек-листа

Минимальный объём: необязательное `checklistVersion` в StartEvaluationRequest. Без него — последняя версия; с ним — точный сохранённый снимок, неизвестная версия даёт понятную ошибку. Список версий уже возвращает GET /api/checklists. Это выбор версий одного чек-листа, не библиотека независимых чек-листов — не заявлять большего.

Проверить две разные шкалы/версии, неизменность предыдущей оценки и запрос к модели с выбранной версией. Не снимать запрет переоценки после апелляции попутно: он защищает текущую историю. Для демо использовать новый диалог, а расширение истории оценок вынести отдельно.
