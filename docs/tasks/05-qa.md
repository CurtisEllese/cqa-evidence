**Обновление Freedom:** [официальные уточнения](../organizer-clarifications.md) имеют приоритет: живой продукт и разумные обоснования; не оптимизируемся под неизвестную формулу. Для калибровки сначала короткий проход 30–45 минут.


Приоритет: **P0**. Задача: [#8](https://github.com/CurtisEllese/cqa-evidence/issues/8). Ветка для тестов/инструкций: `test/release-acceptance` от актуального main. Доступ к репозиторию подтверждён. Это самостоятельный поток качества, не ещё одна реализация backend/UI.

## P0.0. Сценарии, которые жюри может запросить без подготовки

Проверить фильтр грубых ошибок и основания, апелляцию, добавление/изменение критерия и веса, подробный результат конкретного диалога. Затем дать проверяющему самостоятельно поработать 5 минут без подсказок. Сценарий: [live-demo.md](../live-demo.md). Зафиксировать непонятные действия и незакрытые состояния.

## P0.1. Запуск на втором компьютере

- [ ] Клонировать текущий main в чистую папку, пройти README на Python 3.11 и Node.js 22+. Зафиксировать SHA, ОС и версии окружения.
- [ ] Установить зависимости, выполнить contracts:check, npm test и npm run build. Записать фактические результаты, не копировать число тестов из старого отчёта.
- [ ] Проверить пустую рабочую область без ORGANIZER_DEV_URL и ручной импорт. Подключение настоящего Gemini проверить с серверным ключом в локальном окружении; ключ не помещать в issue/скриншот/командную строку с логированием.
- [ ] Работать в отдельной SQLite. Рабочие данные капитана не перезаписывать.

**Результат:** короткая инструкция «чистый клон → работает» или точный блокер: шаг, ожидаемое/фактическое, безопасный лог, SHA.

## P0.2. Матрица обязательных сценариев

Для каждого: PASS/FAIL/BLOCKED, SHA, условия, результат, ссылка на баг. Не считать blocked успешной проверкой.

1. Новый синтетический диалог → настоящий вызов модели → completed → восемь критериев → переход к реальной реплике → экспорт.
2. N/A исключает вес; эталонный пример даёт 85.38; №8 меняет флаг, но не обнуляет сумму. Проверять сервер, не рассчитывать итог в UI вручную.
3. Апелляция → причина → предварительный итог → решение → оригинал и финальный итог сохранены после перезапуска. Один критерий нельзя пересмотреть второй апелляцией поверх завершённой незаметно.
4. Изменённый через UI смысл и шкала 0/2/5 → новый диалог → новая версия; старый результат не меняется. Обязательно проверить найденную ошибку из docs/audit/custom-criterion-repro.json.
5. RU/KZ/EN, bot/system сохраняют ID; бот не засчитывается как оператор; подтверждённая системная идентификация рассматривается как контекст.
6. Невалидный JSON/пропущенный критерий/запрещённый N/A/недопустимая ступень → ограниченная обработка ошибки, без фиктивного балла. Неверный message_id/цитата → needs_review без финального итога. Эмулировать в тестовой среде; не ломать рабочий провайдер.
7. Ошибка или лимит API → видимая ошибка; повтор не создаёт дубликаты активных задач. Перезапуск незавершённой задачи не выдаёт её за готовую.
8. Контрольная группа из 10 синтетических записей → импорт, оценка, экспорт; после доработки Дильназ — через groupId, до неё — через ручной JSON. Ошибка загрузки не уничтожает старые результаты.

Для текущего интерфейса демонстрацию новой версии выполнять на новом диалоге без апелляций: переоценка после апелляции намеренно заблокирована.

## P0.3. Независимая проверка точности

- [ ] Вместе с капитаном выбрать 12–15 разнообразных примеров, выделить часть для настройки и закрытую часть. Похожие сценарии/переводы не разделять между частями.
- [ ] Организовать независимую разметку двумя людьми до просмотра вывода Gemini. Спорные случаи согласовать по рубрике, причину сохранить. KZ размечает участник, понимающий язык; иначе честно отметить отсутствие проверки.
- [ ] Adalbala получает часть для настройки; закрытые ответы не передавать до финального прогона зафиксированной версии. Запустить подготовленную им команду сравнения.
- [ ] Проверить знаменатели метрик: failed/needs_review не исчезают из отчёта, число примеров у каждого языка/канала видно; №8 и N/A вынесены отдельно.

**Результат:** согласованные метрики и каталог ошибок с SHA/model/prompt version. Эталон команды не называть эталоном организаторов. Реальные транскрипты/аудио остаются в приватном рабочем наборе; в Git — синтетические воспроизведения и агрегаты.

## P1. Звонки, мобильный экран и защита

- [ ] Проверить воспроизведение всех пяти выданных звонков, перемотку, недоступное аудио, переход к evidence после доработки UI. Зафиксировать проверку синхронизации, не предполагать её по наличию ISO-меток.
