# Krutoi312: интерфейс контрольного набора и проверяемого результата

Приоритет: **P0** для контрольной загрузки; остальные пункты **P1**. Задача: [#3](https://github.com/CurtisEllese/cqa-evidence/issues/3). Ветка от актуального main: `feat/control-ui`.

## Цель и границы

Проверяющий должен загрузить новый набор, запустить настоящую оценку и быстро понять её основание. Список, карточка, редактор, апелляции и polling уже работают. Их не переписывать. Владелец `src/*`, UI-тестов и оформления — Krutoi312. Сгенерированные типы выпускает Дильназ вместе с серверным контрактом; свои версии DTO не создавать.

## P0. Контрольный group_id

- [x] Добавить подписанное поле «Группа набора» со значением DEV по умолчанию и кнопку «Загрузить набор». Пользователь вводит только идентификатор, не секретную ссылку организатора.
- [x] После первого контрактного коммита Дильназ передавать `groupId` в POST /api/organizer/refresh. Ответ — текущий WorkspaceState. До появления backend поле не должно создавать видимость работающей загрузки.
- [x] Показать фактическую группу, число записей, состояние загрузки и ошибку. Во время запроса блокировать повторный клик; ошибка не очищает существующий список и оценки.
- [x] Убрать безусловную надпись DEV у ручного/контрольного набора. Если происхождение конкретного диалога не известно из API, не приписывать его группе по догадке.
- [ ] Оставить доступным существующий импорт JSON как резерв; рядом коротко объяснить, что можно вставить полный ответ API организаторов или массив записей.
- [ ] Не запускать массовую оценку автоматически после импорта. Дать пользователю открыть новые диалоги и запускать оценку существующей кнопкой; batch — отдельная необязательная функция.

**Приёмка:** DEV → группа из 10 тестовых записей; правильное имя/количество; один запрос на клик; ошибочный ответ сохраняет предыдущие данные; новые записи получают реальную оценку и экспортируются. Ни подписанный URL, ни API-ключ не оказываются в браузерных запросах или bundle.

Отметки выше относятся к локальной ветке `codex/dataset-group-ui` на 7 ноября 2026 года, не к `main`. Реальная загрузка DEV через браузер проверена: 65 записей, источник `live`. Состояния UI проверены на синтетических ответах; команда проверки и исправление ошибки Origin описаны в [документации наборов](../control-datasets.md). Полная приёмка настоящей контрольной группы с оценкой и экспортом остаётся отдельным шагом.

## P1.1. Выбор версии и понятная история

- [ ] Использовать GET /api/checklists для списка сохранённых версий. Показать название/номер выбранной версии до запуска.
- [ ] После серверной реализации передавать `checklistVersion`; по умолчанию выбрать последнюю. Во время обработки показывать снимок версии задачи, а не новое глобальное значение.
- [ ] После изменения критерия старая оценка остаётся на старой версии, новая — на выбранной. Не подставлять новый текст критерия в старый результат.
- [ ] Для диалога с апелляцией объяснить, почему переоценка заблокирована. Для демо смены критерия использовать другой новый диалог; не обходить серверный запрет.

**Приёмка:** v1 и v2 с разными смыслами/шкалами доступны для выбора; запрос содержит выбранную версию; результат отображает именно её. Не называть список версий библиотекой нескольких независимых чек-листов.

## P1.2. Доказательства и звонки

- [ ] Сохранить выделение только проверенных сообщений/диапазонов. Для unverified показывать причину и отсутствие итогового балла.
- [ ] При клике evidence звонка переходить к сообщению и аудиопозиции, если временная привязка подтверждена. Начальное приближение — разница ISO-времени сообщения и первой реплики; оно не гарантирует совпадения с началом файла.
- [ ] Проверить соответствие на записи; при необходимости добавить ручное смещение. Ограничивать позицию диапазоном записи; корректно дождаться metadata; при неизвестной привязке оставить текстовый переход и явное сообщение.
- [ ] В карточке обеспечить быстрый доступ к условию критерия, значению, весу, объяснению, N/A и исходной реплике. Неподтверждённый балл не выдавать за финальный.

**Приёмка:** на одном проверенном реальном звонке 2–3 evidence-перехода приводят к ожидаемым фрагментам; на недоступной записи карточка не ломается; дальнейшая проверка всех пяти записей — Roman. Темп/дикцию по одному тексту не обещать.

## Передача и проверки

Первым передать Дильназ схему расположения поля/состояний; затем работать по её сгенерированным типам. Контрактные изменения в src/services/api.ts и mapper не смешивать с большим редизайном.

Приёмка: production build; JS-контрактные тесты; ручной сценарий новый диалог → настоящая оценка → evidence → апелляция → сохранение/перезагрузка; отдельный новый диалог → изменённая версия. Проверить обычный desktop и узкий экран. Не копировать секретные данные в скриншоты PR; для UI использовать синтетический пример.

Не добавлять сейчас графики, риск-радар, CSI, перенос на Web Components или авторизацию. Все баллы считает backend; браузер не создаёт успешную оценку из заглушки.
