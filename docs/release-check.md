# Итоговая техническая приёмка

Приёмка **8 ноября 2026**, команда **Spooky spooky**. Основание: исходные PDF, приложение Results JSON 1.0 и официальные уточнения Freedom.
Рабочая ветка `codex/consolidated-review-20261107`, база `d4fdae2` из `origin/fix/submission-readiness`: включает актуальные UI, backend v2, evaluator, группы и контекст оценки. Архивная ветка backend v1 не подмешивалась в действующий v2.
Старые аудиты описывают состояние на свою дату. Презентация отложена пользователем.

## Что закрыто

- Восемь начальных критериев, секции по PDF, настраиваемые типы, шкалы, веса и N/A.
- Загрузка группы организатора произвольного размера и ручного JSON; прежние данные не теряются при конфликте или ошибке источника.
- Реальный OpenAI-адаптер `gpt-6-luna`, проверка структуры и ссылок на реплики, явные состояния ошибок и needs_review без выдуманного балла.
- Серверный Decimal-расчёт, N/A исключает вес, грубые ошибки идут отдельным флагом. В карточке показаны баллы с весом, нормированный вес и вклад в итог.
- Фильтр исходных грубых ошибок, объяснение и переход к доказательству; апелляция не стирает исходное обнаружение.
- Апелляции с причиной, отдельным рассмотрением, предварительным пересчётом, исходным и финальным результатом.
- Выбор сохранённой версии для новой оценки. Все запуски доступны через «История оценок», даже если последний завершился ошибкой.
- Модель и версия промпта сохраняются с новым заданием и экспортируются; для старых записей неизвестные сведения не выдумываются.
- В звонках кнопка «К записи» у реплики вычисляет позицию относительно первой метки. Поле смещения позволяет учесть вступление; положение приблизительное. При выходе за длительность показана ошибка.
- Корпоративный интерфейс, запуск без регистрации на localhost, README, модель и оценка стоимости, сценарий защиты до пяти минут.
- Выбор всех сохранённых наборов, явная последовательная оценка набора, остановка после текущего диалога и повтор только ошибок. Навигация сохраняет очередь и контекст таблицы; обновление страницы прекращает оставшуюся клиентскую очередь и восстанавливает статус серверного задания.
- Ошибки бюджета/провайдера останавливают оставшуюся очередь. Рабочий бюджет $0.50; абсолютный разрешённый максимум $5. SQLite-ledger общий для приложения и проверок, учитывает повторные и незавершённые попытки.
- Официальный экспорт выбранной группы JSON 1.0 и отдельная резервная копия v2. Ошибки остаются в результатах с исходными ID. Валидатор сверяет все 8 критериев, типы, формулу, флаг и диапазон исходных реплик.

## Запуск перед защитой

1. Получить проверенную ветку/коммит. Установить зависимости по README; серверный `.env.local` не перезаписывать.
2. Выполнить `npm run contracts:check`, `npm test`, `npm run build`, затем `npm start`.
3. Открыть `http://127.0.0.1:8000`. Это один адрес для UI и API, без отдельного Vite и настройки другого Origin.
4. Если база создана до исправления секций, сохранить исправленный чек-лист новой версией по [инструкции](submission-readiness.md#если-база-уже-создана). Старую базу не удалять.
5. Загрузить DEV или выданную контрольную группу, выбрать версию и оценить новые диалоги. Не выдавать `demo-only-*` за DEV/контроль.
6. Перед стоп-кодом зафиксировать SHA (`git rev-parse HEAD`) и рабочую копию. Для резервной копии SQLite остановить сервер либо использовать SQLite Backup API; одного файла при активном WAL недостаточно.

## Что не заменяется программными исправлениями

- Независимая ручная проверка качества RU/KZ/EN: AI-черновик не является экспертной разметкой. Нет заявления о совпадении с закрытым Ground Truth.
- Фактическая контрольная группа ещё должна быть получена от организаторов. Формат и стоп-код уже известны: [порядок сдачи](official-submission.md), 8 ноября 12:00. После обработки контрольных 10 чатов оба results.json должны оказаться в опубликованном Git-репозитории до стоп-кода.
- Подтверждённый продуктовый справочник. Юрлицо/применимость правил пока не установлены; неутверждённые факты не подключены.
- Репетиция до пяти минут и резервное видео команды. Девять заданий бинго требуют девять реальных фотографий участников.

Прототип предназначен для показа на ноутбуке. Публичный многопользовательский доступ и анализ дикции/интонации не заявляются. Переоценка после апелляции блокируется для сохранности процесса; другой чек-лист демонстрируется на диалоге без апелляции.
