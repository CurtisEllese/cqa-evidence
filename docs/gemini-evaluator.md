# Gemini evaluator: подключение к backend

Реализация: `evaluator/gemini.py`, инструкции: `evaluator/prompt.py`, wire-типы: `contracts/v1.py`. Провайдер выбран пользователем: Gemini. OpenAI для первого запуска не используется.

## Установка и конфигурация

Python 3.11:

```sh
python -m pip install -r requirements-evaluator.txt
```

Серверное окружение или игнорируемый `.env`:

```dotenv
GEMINI_API_KEY=your-local-secret
LLM_PROVIDER=gemini
LLM_MODEL=gemini-3.5-flash-lite
```

Не коммитить заполненный файл. Проверить конфликтующие значения в `.env.local` и окружении: существующие значения окружения при загрузке dotenv не заменяются. Ключ не отправляется браузеру. Модель задаётся конфигурацией, доступ и квота конкретного проекта могут меняться.

## Интерфейс для Дильназ

```python
from evaluator import GeminiEvaluator, EvaluatorSettings, EvaluationFailure, PROMPT_VERSION
from contracts.v1 import EvaluatorInput, validate_output

# Создать ОДИН экземпляр в lifespan FastAPI после загрузки dotenv.
judge = GeminiEvaluator(EvaluatorSettings.from_env())

request = EvaluatorInput(
    conversation=conversation_snapshot,
    checklist=checklist_snapshot,
    knowledge_context=verified_product_facts,
    knowledge_version=knowledge_version,
    prompt_version=PROMPT_VERSION,
)
try:
    result = await judge.evaluate(request)
except EvaluationFailure as exc:
    # exc.error — ErrorBody; обернуть в ErrorResponse с request_id,
    # сохранить failed job. exc.attempts — безопасная телеметрия попыток.
    ...
else:
    report = validate_output(result.output, request.checklist, request.conversation)
    # report.status == needs_review: total_score=null, кандидат отдельно.
    # valid: посчитать баллы Decimal на сервере и сохранить.
    # Перед записью снова проверить expected_hash/версию, не применять к новому тексту.
    ...

# При завершении lifespan:
await judge.aclose()
```

Адаптер не запускает HTTP-сервис, не считает баллы и не записывает SQLite. Он возвращает `AdapterResult`, допускающий неподтверждённые доказательства; backend ОБЯЗАН проверить `validate_output`, построить правильный статус и повторно проверить снимок перед записью. В `feat/ui` уже есть `Repository.record_evaluation(..., expected_hash)`; его текущему внутреннему формату нужен mapper и поддержка needs_review. Не передавать ModelOutput в старое хранилище вслепую.

Реальные данные transcript с PII/конфиденциальной информацией не отправлять в Free tier. Live-проверка по умолчанию использует только вымышленные учебные диалоги, включая вымышленные продуктовые факты. Аудио не отправляется; адаптер оценивает текст звонка и не заявляет акустический анализ.

## Ограничения вызовов и ошибки

- Один запрос в работе на экземпляр; старт не чаще чем раз в 5 секунд. Создавать адаптер один раз на процесс. На первом демо один worker; для нескольких процессов нужен общий ограничитель.
- Максимум два вызова внутри evaluate: общий бюджет на transport retry и исправление структуры. SDK retry отключён (`attempts=1`). Backend не добавляет ещё один цикл повторов вокруг evaluate.
- 429/временные сетевые ошибки допускают один повтор. Retry-After/RetryInfo свыше 30 секунд возвращается вызывающему коду вместо долгого ожидания. Это не отменяет лимиты токенов/суток проекта.
- 400/401/403/404 — без повторов, `PROVIDER_UNAVAILABLE`, retryable=false; проверить конфигурацию/доступность модели/схему. Отказ — `MODEL_REFUSAL`, без повтора.
- Неверный JSON, неполный ответ, пропущенный критерий, недопустимая ступень или N/A — одна попытка исправления, затем `MODEL_OUTPUT_INVALID`.
- Ошибки цитат/ссылок возвращаются без дополнительного вызова как кандидаты на review. Проверка наличия цитаты не подтверждает правильность её интерпретации.
- Сырые сообщения API/ключи/транскрипты в телеметрию не попадают. Обработчик `on_attempt(event)` может сохранить безопасные события в журнал; он должен быть быстрым и не выбрасывать исключений. События ошибок имеют неизвестный usage=null, если провайдер его не вернул; отсутствие usage не означает нулевой расход.
- Provenance суммирует известные токены всех полученных ответов и включает thinking tokens. Стоимость null: тариф/квота не угадываются. Версия модели берётся из ответа, если доступна.

## Проверки

Без ключа и сетевых вызовов:

```sh
python -m pip install -r requirements-contracts.txt -r requirements-evaluator.txt
python -m pytest tests/test_contracts.py tests/test_evaluator.py -q
```

Реальная проверка всех восьми критериев на синтетике RU/KZ/EN, включая текст звонка:

```sh
python -m evaluator.smoke --live --report artifacts/gemini-smoke.json
```

Без `--live` запросы не отправляются. Команда печатает только статусы, метрики сравнения, различия значений и usage, а не ключ/тексты. Код выхода 0: все выбранные случаи прошли структурную/доказательную проверку и совпали с учебными метками; 1: расхождение, review или API-сбой; 2: неверная конфигурация/неожиданная ошибка.

`evaluator/fixtures/synthetic.json` — три простых учебных примера. Их ожидаемые значения подготовлены для проверки подключения и НЕ являются Ground Truth организаторов, независимой экспертной разметкой или доказательством качества на скрытом наборе. Копия рубрики взята из текущей ветки UI только как fixture; runtime получает актуальную рубрику от backend.

Для своей обезличенной размеченной выборки: `--cases path/to/cases.json`. Формат — массив `{request: EvaluatorInput, expected: {criterion_id: integer|null}}`. Отчёт разделяет точное совпадение, ошибки N/A, флаги и MAE нормированной шкалы только для применимых числовых критериев. Метрику итогового балла считать модулем backend. Не смешивать настройку промпта и независимую проверку; калибровка с экспертом остаётся отдельной работой.

Для backend-кэша есть `request_fingerprint(request, settings)`: учитывает реальный текст, рубрику, язык/канал, знания, промпт, модель и параметры. Адаптер сам результаты не кэширует; смена рубрики должна запускать новый расчёт.

SDK и режим JSON сверены с [официальной документацией Google Gen AI](https://googleapis.github.io/python-genai/). Условия обработки данных: [Gemini API terms](https://ai.google.dev/gemini-api/terms).

Проверка изменения критерия и инъекции в реплике:

```sh
python -m evaluator.smoke --live --cases evaluator/fixtures/adversarial.json --report artifacts/gemini-adversarial.json
```

## Фактически проверено 7 ноября 2026

Python 3.11.0, google-genai 3.0.0, Pydantic 2.14.3. 49 локальных тестов прошли: контракты, структурные ошибки/repair, запрет N/A, доказательства, лимит повторов, отказ, 429/RetryInfo, тайм-аут/сеть, сериализация запросов, безопасная телеметрия и метрики.

Первый живой прогон выявил ошибки N/A на KZ и неподтверждённые доказательства. В промпте v2 приоритет проверки применимости уточнён; модель возвращает ID, а quote=null — текст извлекается из исходника сервером. После этого повторены те же три случая (это настройка, НЕ holdout):

| Случай | Согласие с учебными метками | Статус | Вход/выход, токены | Время evaluate |
|---|---|---|---|---|
| RU, 8 критериев | 8/8 | valid | 2096 / 1061 | 4.71 с |
| KZ, текст звонка, 8 критериев | 8/8 | valid | 2144 / 1007 | 4.35 с |
| EN, 8 критериев | 8/8 | valid | 2084 / 984 | 5.10 с |
| Новый смысл критерия, шкала 0/2/5 | 1/1 | valid | 1102 / 144 | 2.66 с |
| Приветствие только бота + инструкция клиента поставить высокий балл | 1/1 | valid | 1032 / 146 | 5.37 с |

Все пять итоговых вызовов завершились с первой попытки. Время evaluate включает возможное ожидание локального ограничителя; это не чистая задержка API. Проверена модель gemini-3.5-flash-lite. Стоимость не оценивалась, новых оплат не подключалось. Это не измерение качества на реальных диалогах и не подтверждение готовности UI: интеграция jobs/SQLite остаётся за backend.
