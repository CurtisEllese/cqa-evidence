# Gemini: готовый адаптер активного v2

Точка подключения — `EVALUATOR_ADAPTER=evaluator.v2:evaluate`. Адаптер принимает `backend.contracts.v2.EvaluationRequest` и возвращает `ModelResponse`; опубликованный v1 не импортируется. Чек-лист, значения Decimal-строками и evidence передаются по активному контракту приложения.

## Запуск

Установить Python 3.11 и зависимости:

```sh
python -m pip install -r backend/requirements.txt
```

В игнорируемом `.env.local` либо серверном окружении:

```dotenv
GEMINI_API_KEY=your-local-secret
LLM_PROVIDER=gemini
LLM_MODEL=gemini-3.5-flash-lite
EVALUATOR_ADAPTER=evaluator.v2:evaluate
```

Не перезаписывать существующие ORGANIZER_DEV_URL и DATABASE_PATH. Значения окружения и `.env.local` имеют приоритет над `.env`. Перезапустить backend. Ключ не передаётся в UI и не коммитится.

Приложение уже умеет загружать этот async entrypoint. POST `/api/evaluations` получает `{schema_version: "2.0", conversationId: "..."}`, возвращает 202; GET по ID показывает задачу. UI продолжает использовать текущий v2 mapper. Первый реальный запуск выполнять только на синтетическом или проверенно обезличенном диалоге.

## Границы ответственности

- Адаптер делает ровно ОДИН provider call на вызов. SDK retry отключён (`attempts=1`). Retry/repair до двух вызовов суммарно на job делает существующий `EvaluationService`. `repair_feedback` передаётся модели вместе с исходным снимком.
- Backend проверяет шкалы, N/A, полноту критериев и доказательства, рассчитывает баллы и сохраняет SQLite. Плохая ссылка/цитата даёт needs_review без итога; структурная ошибка — исправление через backend и затем failed_validation. Адаптер не подменяет ошибки нулём или N/A.
- Очередь backend сериализована (одна задача), как и обращения к Gemini. Между стартами API минимум 5 секунд. Это не обещание доступной суточной/токенной квоты. Тайм-аут entrypoint 45 секунд внутри 60-секундного лимита backend.
- 401/403/400/404 не повторяются автоматически. 429/временные сбои сообщаются через AdapterFailure. Если провайдер требует ждать более 30 секунд, retryable=false: существующий backend ограничивает ожидание 30 секундами и не должен повторить раньше разрешённого времени.
- Неполный/невалидный JSON передаётся backend как очищенная ошибка разбора, отказ — MODEL_REFUSAL. Сообщения исключений провайдера, ключи и тексты переписки в ошибку не включаются.
- Для provider-схемы убираются неподдерживаемые Google ограничения JSON Schema. Полная локальная Pydantic-валидация и inspect_output остаются строгими; схема API и сгенерированные типы приложения не меняются.
- Модель возвращает существующие ID и quote=null; оригинальный текст извлекается сервером. Наличие исходной реплики само по себе не доказывает правильность интерпретации.
- Функция использует текущие criteria/allowedValues/naCondition, а не восемь захардкоженных правил. Сначала определяется применимость, затем балл. Входные сообщения остаются данными, в том числе инструкции внутри них. Для звонков нет выдуманного анализа дикции по одному тексту.

## Телеметрия

Логгер `evaluator.v2` уровня INFO пишет безопасный JSON `gemini_attempt`: хеш входа, версия промпта, реальная модель, исход запроса, время, известные входные/выходные токены (включая thinking). У тестового класса есть callback on_attempt. Ни ключ, ни диалог не записываются. Рабочий entrypoint сохраняет события в игнорируемый local-data/gemini-usage.jsonl (путь можно задать GEMINI_USAGE_LOG); ошибки записи не уничтожают полученный результат. Действующий ModelResponse не содержит provenance, и адаптер не добавляет неразрешённых полей. Неизвестный usage остаётся null; стоимость не угадывается.

## Проверки

```sh
python -m pytest tests/test_gemini_v2.py tests/test_contracts.py backend/tests -q
python scripts/generate_contracts.py --check
python -m evaluator.smoke_v2 --live --report artifacts/gemini-active-v2.json
python -m evaluator.smoke_v2 --live --cases evaluator/fixtures/adversarial_v2.json --report artifacts/gemini-adversarial-v2.json
```

Без `--live` smoke не вызывает API. Fixtures — полностью вымышленные RU/KZ/EN диалоги и учебные факты; KZ использует ISO-время звонка. Дополнительные случаи проверяют замену смысла критерия/шкалы и приветствие только бота вместе с попыткой инъекции клиента. Эти метки подготовлены для проверки механики, не являются Ground Truth организаторов или независимой экспертной оценкой. Реальные персональные/конфиденциальные данные нельзя отправлять в Gemini Free tier.

Остаётся работа с продуктовым экспертом: разметить обезличенную выборку реальных сценариев, отдельно измерить N/A/флаг/ошибки критериев. Backend сейчас формирует knowledgeFacts=[]; наполнение подтверждённым справочником является отдельной интеграцией. Нельзя выдавать успешный smoke за точность на скрытых диалогах.

Официальный SDK: [Google Gen AI](https://googleapis.github.io/python-genai/). Условия: [Gemini API terms](https://ai.google.dev/gemini-api/terms).

## Проверенные результаты

7 ноября 2026, Python 3.11.0, google-genai 3.0.0, gemini-3.5-flash-lite:

- Активный v2: три живых учебных диалога RU/KZ/EN, включая текст звонка: 24 из 24 значений совпали с синтетическими метками, ошибки evidence отсутствовали.
- Новая формулировка критерия со шкалой 0/2/5 и пример с приветствием только бота/инъекцией клиента: 2 из 2 ожидаемых решений, без ошибок evidence.
- Полный HTTP-сценарий на отдельной временной SQLite: импорт вымышленного диалога, новая версия чек-листа с одним критерием, POST оценки → 202 → completed → score=100, затем GET после перезапуска сохранил результат. Рабочие DEV-данные не менялись.
- Все вызовы итогового v2 smoke завершились за одну попытку. Примерные времена provider call: RU 5.39 с, KZ 5.28 с, EN 3.63 с. Вход/выход: RU 1813/1143, KZ 1928/1040, EN 1802/1050 токенов. Стоимость не выдумывалась и записана null.

Схема провайдера была упрощена после фактического HTTP 400 на полной v2-схеме; локальный строгий контракт сохранён. Эти же учебные примеры использовались при настройке, поэтому результаты не являются независимым измерением точности.
