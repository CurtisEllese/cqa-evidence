# Живая демонстрация и самостоятельная проверка жюри

Основание: [уточнения организаторов](organizer-clarifications.md). Сценарий — для работающей сборки, не для показа заранее подставленных оценок.

## Подготовка до выхода

- Зафиксировать SHA, модель, prompt version и рабочую базу; проверить ключ/квоту на сервере. Секреты не показывать в терминале или браузере.
- Импортировать разрешённые примеры и реально оценить их. Для безопасной репетиции есть [синтетический набор](../demo/jury-scenarios.json), в нём нет баллов или ответов модели. Он не является Ground Truth.
- Оставить хотя бы один новый пример неоценённым для запуска на сцене. Для проверки новой версии взять диалог без апелляции: текущая реализация блокирует переоценку после апелляций.
- Проверить готовый фильтр грубых ошибок, выбрать «Есть грубые ошибки» и открыть основание исходного флага.
- Открыть приложение, убрать лишние вкладки. Работать с ноутбука; самостоятельный доступ жюри к локальному интерфейсу не требует срочного публичного деплоя.

## Пять минут

Пять минут — длительность самого показа по гайду. [Позднее официальное уточнение](https://t.me/c/4473389149/4/3396) ограничивает весь выход вместе с вопросами 8–10 минутами; оставляем время на вопросы внутри этого предела.

**0:00–0:20 — задача.** «Мы помогаем специалисту контроля качества быстро проверить разговор: система оценивает по настраиваемому чек-листу, показывает основания и сохраняет историю пересмотра».

**0:20–1:10 — список и грубые ошибки.** Показать фильтр, открыть найденный разговор, критерий №8 и исходную реплику. Объяснить: флаг отдельный, сумма не обнуляется. Показать, что низкий общий балл и грубая ошибка — разные признаки. Если флаг изменён апелляцией, различить исходный и финальный.

**1:10–2:10 — новая оценка.** Запустить ранее неоценённый диалог. Показать обработку, итог, один N/A и его причину, один переход к источнику. Не обещать время по двум коротким тестам. При задержке перейти к уже реально вычисленному примеру, честно обозначив это; к новому вернуться после завершения.

**2:10–3:10 — апелляция.** Выбрать критерий, написать содержательный комментарий. Открыть отдельное рассмотрение, указать причину решения, сохранить. Показать исходный и финальный результат, затем обновить страницу. На синтетической репетиции можно намеренно менять значение ради проверки интерфейса, но это нужно назвать техническим тестом, не экспертным исправлением.

**3:10–4:30 — гибкость.** По просьбе жюри добавить/изменить критерий либо вес, сохранить новую версию. На другом диалоге запустить новую оценку и показать номер версии и новое правило. Если меняется только вес, не утверждать, что модель сама считает арифметику: это серверный расчёт. При смысловой ошибке показать объяснение и признать ограничение, не подменять ответ.

**4:30–5:00 — контроль и ограничения.** «Неподтверждённое доказательство не становится финальным баллом. Неизвестные продуктовые факты и повреждённый текст отмечаются. Исходный результат и ручной пересмотр сохраняются отдельно». Указать проверенный SHA и фактически сделанную проверку качества без заявления о совпадении с закрытым эталоном.

## Пять минут без подсказок команды

Roman даёт проверяющему задания в произвольном порядке:

1. Найти диалоги с выявленным грубым нарушением и объяснить основание.
2. Открыть конкретный диалог и найти сообщение-доказательство.
3. Подать апелляцию и найти её в очереди.
4. Изменить вес/добавить критерий и понять, к каким оценкам применяется версия.
5. Узнать, почему один результат не завершён или требует проверки.

Фиксировать необходимость подсказок, непонятные названия, потерю контекста, ошибочные клики и время до результата. Это практическая проверка удобства, не новый публичный рейтинг.

## Резервы

- Нет доступа к API организатора → импорт заранее полученного разрешённого JSON; явно назвать источник.
- Нет доступа к модели → показать сохранённые реальные результаты и явную ошибку нового запуска; не выдавать сохранённый результат за новый анализ.
- Не играет аудио → показать транскрипт/ссылку и ограничение; не приписывать модели анализ дикции.
- Сбой демонстрации → резервное видео с подписью, что это запись. Не заменять им основной план живой защиты.

Вопросы организаторам для капитана: точное время стоп-кода и часовой пояс; контрольный group_id/способ получения; формат и канал сдачи результатов/репозитория. Внутреннюю формулу отбора больше не запрашиваем.
