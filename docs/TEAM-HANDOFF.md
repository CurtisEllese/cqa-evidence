# Передача CQA команде

## Сначала прочитать

Активный контракт приложения — [v2.0](contracts-v2.md), источник истины `backend/contracts/v2`. Опубликованный `contracts/v1.py` и его тесты остаются замороженной версией. Не импортируйте типы v1 в новый адаптер и не отправляйте старый snake_case-конверт в v2 API. Изменение версии сделано явно из-за несовместимых полей и десятичных значений.

[README](../README.md) содержит запуск Python 3.11/Node.js и команды проверки. [ADALBALA.md](ADALBALA.md) описывает единственную точку подключения модели. Готовый Gemini-адаптер и его настройка описаны в [gemini-evaluator.md](gemini-evaluator.md); актуальные результаты приёмки — в [командном аудите](team-audit-2026-11-07.md).

## Ответственность и файлы

| Часть                                        | Граница                                                                             |
| -------------------------------------------- | ----------------------------------------------------------------------------------- |
| `backend/contracts/v2`                       | Pydantic v2, входные/выходные DTO, явный codec старых внутренних моделей            |
| `scripts/generate_contracts.py`              | Генерация JSON Schema и TypeScript; `--check` выявляет рассинхронизацию             |
| `contracts/v2`, `src/generated/contracts.ts` | Сгенерированные артефакты; не редактировать вручную                                 |
| `backend/domain.py`                          | Нормализация, официальный чек-лист, детерминированная проверка и Decimal-арифметика |
| `backend/repository.py`                      | SQLite, транзакции, версии, исходные оценки и апелляции                             |
| `backend/evaluator.py`                       | Вызов адаптера, проверка ответа и ограниченный repair                               |
| `backend/app.py`                             | HTTP API, задачи, обработка ошибок и раздача `dist`                                 |
| `backend/media.py`                           | Безопасное разрешение HTML-плееров организатора и потоковое аудио                   |
| `src`                                        | UI, черновики, polling задач и явный mapper wire → view model                       |

В браузере нет источника финальных баллов, назначения серверных версий и постоянного хранилища. Проверка формы нужна для обратной связи; backend повторно проверяет каждое значение. Внутренний `binary`/числовой view model допустим только за mapper; сеть использует `yes_no` и десятичные строки.

## Маршруты

В JSON-телах операций ниже обязателен `schema_version: "2.0"`. Исключение — исходный импортируемый текст: он находится внутри `ImportRequest.text` и нормализуется сервером как внешний формат организатора.

| Метод | Путь                                 | Назначение / тело помимо `schema_version`                                  |
| ----- | ------------------------------------ | -------------------------------------------------------------------------- |
| GET   | `/api/health`                        | Состояние приложения и доступность оценщика                                |
| GET   | `/api/state`                         | `WorkspaceState`: данные, метаданные DEV, revision, evaluationAvailable    |
| POST  | `/api/organizer/refresh`             | Обновление DEV; дополнительных полей нет                                   |
| POST  | `/api/import`                        | `{text}` — строка исходного JSON                                           |
| GET   | `/api/conversations`                 | Поиск `q`, `language`, `channel`, `offset`, `limit`                        |
| GET   | `/api/conversations/{id}`            | Диалог, сообщения, оценка и серверные итоги                                |
| GET   | `/api/checklists`                    | Сохранённые версии                                                         |
| POST  | `/api/checklists/{id}/versions`      | `{checklist, expectedVersion}`; конфликт версии → 409                      |
| POST  | `/api/evaluations`                   | `{conversationId}` → 202 + `EvaluationResult`; без адаптера → 503          |
| GET   | `/api/evaluations/{id}`              | Текущий прямой `EvaluationResult`, включая состояние задачи                |
| POST  | `/api/appeals`                       | `{conversationId, evaluationId, criterionId, comment}`                     |
| POST  | `/api/appeals/{id}/preview`          | `{status, decision, newValue}` — пересчёт без записи                       |
| POST  | `/api/appeals/{id}/decision`         | То же тело; решение сохраняется сервером                                   |
| GET   | `/api/export`                        | Экспорт серверного рабочего пространства                                   |
| GET   | `/api/conversations/{id}/export`     | Диалог и связанные апелляции                                               |
| GET   | `/api/evaluations/{id}/export`       | Экспорт сохранённой оценки                                                 |
| GET   | `/api/conversations/{id}/audio`      | Поток, Range/206/416                                                       |
| GET   | `/api/conversations/{id}/audio-page` | Отдельная локальная страница воспроизведения                               |
| POST  | `/api/migrate`                       | `{data}` — специальная проверяемая миграция прежнего браузерного состояния |

Для принятой апелляции `newValue` обязателен: десятичная строка или явный null для разрешённого N/A. Пропущенное поле не равно N/A. Сервер проверяет шкалу сохранённой оценки, а не последнюю редакцию чек-листа.

## Интеграция оценщика

Реализованный entrypoint: `async evaluate(request: EvaluationRequest) -> ModelResponse` в `evaluator/v2.py`; настройте `EVALUATOR_ADAPTER=evaluator.v2:evaluate`. Это вызов Python внутри FastAPI; HTTP остаётся только между адаптером и выбранным провайдером. Нет отдельного model-worker endpoint и нет маршрута, куда браузер может загрузить произвольный результат.

Backend принимает задачу, фиксирует снимок чек-листа и хеш диалога, сохраняет состояние в БД, затем вызывает адаптер. Не обращайтесь напрямую к `Repository.record_evaluation` из адаптера: проверка, арифметика и запись выполняются оркестратором. Адаптер не возвращает итоговые баллы и не изменяет БД.

Состояния: `queued`, `running`, `completed`, `needs_review`, `failed_validation`, `failed`, `retryable`. UI опрашивает GET по ID; не считает сам, что запрос завершился успешно. Только `completed` содержит Score. Непроверенное доказательство оставляет кандидатов с `needs_review` и `score: null`; в остальных ошибочных/незавершённых состояниях финального балла тоже нет.

Общий лимит — два вызова адаптера на задачу, включая единственный repair. Не добавляйте независимые SDK-retry поверх этого лимита. `repair_feedback` содержит структурированные замечания. Перезапуск сервера должен оставлять незавершённую работу в явном состоянии повторного запуска; он не должен выдавать её за завершённую.

Наличие ключа и имени модели не заменяет реализацию адаптера. Без него `evaluationAvailable` выключен, POST возвращает 503. Реальные диалоги не получают синтетические оценки; тестовые адаптеры используются только в изолированных тестах.

## Проверка доказательств

ID реплики имеет вид `{conversationId}-m1`, `-m2`, … по исходному порядку всех ролей; отдельный `message_index` начинается с нуля. Нельзя фильтровать bot/system перед присвоением ID или считать ID индексом массива UI.

Цитата — точная подстрока исходного сообщения, без нормализации. Отсутствие действия подтверждается диапазоном, N/A — причиной и соответствующей репликой/диапазоном. `source_text` и `verification_status` назначает backend. Ссылка на существующую реплику ещё не подтверждает смысловую правильность решения модели.

UI должен показывать `unverified` и причину, не подставляя сгенерированную цитату в исходный transcript. Для `needs_review` не показывать предварительную арифметику как финальный результат и не разрешать незаметное повышение статуса через клиентский пересчёт.

Для `needs_review` сейчас доступен просмотр кандидатов. Отдельного endpoint подтверждения/исправления evidence нет; после исправления входа или адаптера создаётся новая задача. Апелляции создаются только для завершённых сохранённых оценок.

## Сохранность и совместная работа

SQLite использует транзакции, foreign keys и WAL. Чек-лист сохраняется как новая версия; исходная оценка неизменяема. Решения апелляций хранятся отдельно. Проверка хеша не позволяет сохранить ответ модели поверх изменившегося диалога. Обновление DEV не должно уничтожать историю оценок.

Прежний localStorage переносится через специальный маршрут, который не принимает браузерные «готовые оценки» за доверенный результат. При конфликте сохраняйте исходную копию для разбора. Внутренний числовой codec не разрешает отправлять JSON numbers в decimal-поля v2.

Секреты, переписки, аудио, SQLite и `tmp/qa` не публикуются. Для публичного размещения нужны авторизация, роли, HTTPS и резервное копирование. Текущий локальный режим этого не предоставляет.

## Перед PR

```powershell
.venv311/Scripts/python.exe scripts/generate_contracts.py --check
npm test
npm run build
```

Если менялись модели, сначала запустите генератор без `--check` и включите generated-артефакты в тот же PR. Проверьте строгий wire v2, несовместимость v1, Decimal round-trip, границы шкал, N/A, точные цитаты/диапазоны и сохранение `needs_review` без итога. Property-based тесты дополняют примеры, а не заменяют API и браузерные сценарии.

Смена провайдера и подтверждение качества — отдельные шаги. Отчёт о готовности должен различать успешный smoke-вызов API, проход тестов контрактов и реальное совпадение с экспертной разметкой.
