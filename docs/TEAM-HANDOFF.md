# Передача фронтенда и бэкенда команде

## Границы ответственности

`src` — React-интерфейс. Store получает снимок GET `/api/state` и вызывает серверные операции. В браузере нет нормализации импорта, формулы оценки, назначения версий/решений и постоянного хранилища. Клиентская проверка форм служит обратной связи; сервер повторно проверяет все значения.

`backend/domain.py` — официальный чек-лист, нормализация, строгая валидация результатов/доказательств и расчёт. `backend/repository.py` — транзакции SQLite, неизменяемые версии и исходные оценки, апелляции. `backend/app.py` — HTTP API и выдача готового фронтенда. `backend/media.py` — разрешение HTML-плееров заказчика и потоковое аудио. Старый Node-адаптер удалён.

## Подключение оценщика

В backend вызывайте `Repository.record_evaluation(conversation_id, evaluation, expected_hash)` после успешного ответа модели. Передавайте неизменённый снимок сохранённого чек-листа, результаты всех критериев и доказательства из реальных ID сообщений. `expected_hash` обязателен и берётся из разговора до запуска модели. Сервер проверяет хеш, существование версии, диапазоны/N/A, покрытие критериев и доказательства; назначает ID, время и сохраняет исходный результат. Публичного маршрута для загрузки произвольных браузерных «оценок» нет.

Затем реализуйте POST `/api/evaluations`, состояние задач и реальный флаг `evaluationAvailable`. Ключ/модель в .env.local не активируют несуществующий адаптер. Ошибку модели нельзя превращать в нулевую или успешную оценку.

## Сохранность и совместная работа

SQLite использует транзакции, foreign keys, WAL и ожидание блокировки. Версия чек-листа проверяется при сохранении; повторное решение апелляции запрещено. Обновление текста исключает устаревший балл из текущего диалога, но история оценок остаётся в БД. Переход к старой оценке предусмотрен серверным GET по ID; полноценный экран истории версий — отдельная задача.

Перенос прежнего localStorage не принимает сгенерированные браузером оценки; при расхождении данных или конфликте чек-листа сообщает об ошибке и оставляет исходную копию. На сервере не сохраняются демо-наборы.

Текущий общий снимок содержит все 65 транскриптов для небольшого набора. При росте данных UI можно переключить на серверную пагинацию и отдельную загрузку карточки — список API уже поддерживает это. Вкладки обновляют данные при загрузке и собственных изменениях; автоматическое оповещение об изменениях других участников пока не добавлено.

Перед публичным размещением нужны авторизация, роли, HTTPS и резервное копирование. Конфигурация сейчас разрешает только локальный доступ. Запуск и проверки — в README.
