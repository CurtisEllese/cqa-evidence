# Передача фронтенда команде

## Что работает

Фронтенд получает DEV через `/api/organizer/dataset`: GET возвращает проверенную локальную копию (либо загружает её при отсутствии), POST обновляет из API заказчика. Серверный адаптер `server/organizer.mjs` читает `ORGANIZER_DEV_URL`; подписанный URL не передаётся браузеру. Проверяются группа DEV, число 65, отсутствие повторяющихся ID. Ошибка обновления сохраняет предыдущую копию и видима пользователю.

Ответ адаптера: `{ payload, fetchedAt, source: "live" | "cache" }`, где payload — исходная обёртка API заказчика. Нормализация расположена в `src/services/organizer.ts` и `src/domain/import.ts`, состояние — `src/store.tsx`. При обновлении сохраняются ручные импорты и оценки неизменённых транскриптов; устаревшие исходные записи заменяются.

## Что подключить дальше

Backend-инженеру: перенести безопасный запрос DEV и хранение в общий FastAPI backend по architecture.md, добавить постоянные версии чек-листов, оценки и решения по апелляциям. Сейчас локальный Node-адаптер встроен только в dev/preview Vite и слушает localhost.

AI-инженеру: реализовать оценщик официальных восьми критериев, доказательства по ID сообщений, исключения N/A и отдельный флаг грубых ошибок. Фронтенд не вычисляет ответы модели и не генерирует тестовые баллы. `evaluationAvailable` остаётся false до подключения действующего оценщика. Формат Evaluation и CriterionResult описан в `src/domain/types.ts`; `scoreEvaluation` отвечает только за детерминированный пересчёт полученных результатов.

Frontend-инженеру: заменить локальное хранение в StoreProvider серверными операциями, подключить реальный запуск оценки, привести сетевые DTO к согласованным контрактам backend. В карточке поддержаны разбор критериев, доказательства, исходный и пересчитанный результат, апелляции. Экраны без оценок показывают честное ожидание подключения сервиса.

## Критические правила

- Официальные шкалы: консультация 0/5/10/15/20, ведение диалога 0/4/7/10. Формула и ограничения N/A — в requirements.md.
- Флаг грубой ошибки не обнуляет итог. Контрольный пример — 85,38.
- Нельзя придумывать имя оператора, дату чата или позицию аудио из ISO-времени. API не предоставляет эталонных оценок.
- Переписки, аудио, .env.local, local-data, скриншоты с переписками и разметка не должны попадать в Git.
- Тестовые синтетические записи существуют только внутри тестов, не загружаются в приложение.

Запуск и команды проверок — в README.md. Доступ к DEV каждый участник настраивает локально по материалам организаторов.
