# OpenAI API: подключение оценщика

Текущий провайдер — OpenAI Responses API. Настройка на сервере в `.env.local`:

```dotenv
EVALUATOR_ADAPTER=evaluator.provider:evaluate
LLM_PROVIDER=openai
LLM_MODEL=gpt-5.4-mini-2026-03-17
OPENAI_API_KEY=ваш_проектный_ключ
```

Существующий файл не заменять целиком: сохранить ORGANIZER_DEV_URL, DATABASE_PATH и остальные настройки. Ключ никогда не добавлять в Git, README, задачи или VITE-переменные. После изменения настроек перезапустить backend (`npm run backend` либо общий `npm run dev`). Для запуска на другом компьютере нужен его собственный локальный файл с разрешённым проектным ключом; Git передаёт только код.

`OPENAI_API_KEY` — ключ API, не пароль/сессия ChatGPT. Применимость подписки или API-кредитов проверяется в конкретном проекте; приложение не предполагает доступность квоты. Модель настраивается через LLM_MODEL; начальный выбор GPT-5.4 mini проверяется живым запросом. Доступность других моделей не гарантируется.

## Поведение

- Контракт EvaluationRequest/ModelResponse v2, серверный расчёт, проверка доказательств и история апелляций сохраняются.
- Критерии и их шкалы приходят в запросе; ответы по ID диалога не подставляются. Общая инструкция находится в `evaluator/prompt.py`.
- Strict Structured Outputs сохраняет ограничения десятичных строк. N/A — JSON `null`, не строка `"null"`, не ноль. Полная локальная валидация остаётся обязательной.
- Один вызов адаптера — один HTTP-запрос. Общий предел backend — две попытки, включая исправление структуры/шкалы. Скрытых повторов SDK и автоматического перехода на Gemini нет.
- Отказ модели, таймаут, 401/403, отсутствие модели и исчерпание квоты не превращаются в оценки. Длительный Retry-After и insufficient_quota не вызывают быстрый повтор.
- Backend отправляет OpenAI только текущий запрос оценки: сообщения, снимок чек-листа и переданные продуктовые факты. Использование DEV с OpenAI отдельно разрешено капитаном. Ключ авторизации передаётся только официальному API; подписанная ссылка организатора и база SQLite в запрос не входят.
- `store=false`; это параметр хранения ответа API, не заявление о полном отсутствии хранения данных у провайдера.
- `local-data/openai-usage.jsonl` содержит модель, версию промпта, хэш входа, расход токенов, время и исход попытки. Тексты/ключи не логируются. Цена не выдумывается: cost_usd остаётся null.

## Проверка

Обычные тесты не требуют ключа и не отправляют данные:

```sh
npm run contracts:check
npm test
npm run build
```

Явная живая проверка трёх синтетических случаев RU/KZ/EN, включая звонок:

```sh
# macOS / Linux
.venv311/bin/python -m evaluator.smoke_v2 --live --report local-data/openai-smoke.json
# Windows
.venv311/Scripts/python.exe -m evaluator.smoke_v2 --live --report local-data/openai-smoke.json
```

Этот инструмент делает один запрос на случай и показывает ошибки первой попытки. Он не имитирует backend repair. Синтетические ожидаемые ответы проверяют интеграцию, но не являются независимым Ground Truth и не доказывают точность на DEV.

Резервный Gemini остаётся доступен только при явной смене LLM_PROVIDER=gemini, LLM_MODEL и GEMINI_API_KEY с перезапуском. Старый прямой `evaluator.v2:evaluate` всегда означает Gemini; для переключения использовать общий `evaluator.provider:evaluate`.

Официальные источники: [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [GPT-5.4 mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini).

## Проверено 7 ноября 2026

Живой синтетический прогон выбранной модели: три случая RU/KZ/EN, 24/24 ожидаемых решений, все ссылки на доказательства прошли проверку, 3.7–4.8 секунды на запрос. [Отчёт](audit/openai-smoke.json). Это малая отладочная выборка, не доказательство качества на скрытом наборе. В раннем прогоне найдены и устранены проблемы формата N/A и смешивания message_id с диапазоном; backend не принимал неподтверждённый итог. GPT-4.1 mini не выбран из-за ошибок в этих проверках.

Дополнительно проверен реальный путь EvaluationService → OpenAI → проверка доказательств → SQLite: задача completed, восемь результатов и одна сохранённая оценка в отдельной временной базе. Общие проверки: 335 Python-тестов, 6 JS-тестов, 32 артефакта схем и production build.
