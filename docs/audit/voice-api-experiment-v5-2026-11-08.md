## Задача и конкретный предлагаемый проход

Один проход по тем же шести WAV N01–N06 из V4: шесть независимых запросов `gpt-audio-1.5`, по одному на файл, без повторов, без общения с прежним экспериментальным чатом. Каждый запрос содержит только **одну запись, её независимо извлечённые метрики и нейтральный ID**. Модель не получает private_role, исходные имена, информацию о парах, ожидаемые 2.5 s / 1.8× / SNR, reference transcript, предыдущие ответы или результаты парной проверки.

Контур: WAV → собственный небольшой DSP → численные признаки с ограничениями → audio + measurements → краткое JSON-наблюдение модели. Результаты будут разделены на **DSP**, **интерпретацию модели с метриками** и **проверку известных преобразований**. Если модель правильно перескажет переданный ей интервал паузы, это улучшение общей системы, а не доказательство улучшившегося слуха GPT.

Фиксированный порядок N01–N06, modalities=text, max_completion_tokens=800, n=1, stream=false, store=false; остальные sampling-параметры не задаются, как в V4. Максимум три события пауз в ответе. Не запрашиваются цитаты, транскрипция, chain-of-thought, баллы, эмоции или выводы о личности. Дикция не выводится из шума или быстрого темпа.

## Методы: одинаковые параметры для всех шести

Собственная реализация на уже имеющихся numpy2.1.2/scipy1.14.1 и stdlib; чужой код не импортирован/не исполнен. Новых зависимостей и моделей нет. WAV читаются без модификации; каналы усредняются, анализ при исходном sample rate.

|---|---|---|
| Абсолютная тишина | RMS-кадры20 ms, шаг10 ms; ≤−40 dBFS, интервал≥0.30 s | Зависит от gain. В текущих KZ результат явно загрязнён тихой речью; не считать speech silence |
| Адаптивная energy activity | Порог max(−60, min(p10+8, p90−12)) dBFS; заполнить внутренние неактивные gaps≤0.10 s, удалить active bursts<0.08 s; неактивные интервалы≥0.30 s | Это энергетическая маска, не обученный speech VAD; шум/музыка могут считаться речью |
| Фон | p10/p90 энергии, p10 ненулевых кадров >−90 dBFS; доля почти нулевых кадров; spectral flatness в200–7000 Hz для20% самых тихих ненулевых кадров | Не SNR. Неизвестны речевая активность, источник фона и усиление; tonal noise не обязан повышать flatness |

| Контроль уровней | RMS/peak/clipped sample fraction | Не качество речи и не SNR |

## Нужен ли дополнительный ASR

В предложенный проход дополнительные ASR-вызовы **не включены**. Поэтому результат V5 по скорости ограничен акустическими proxy и восприятием модели.

Более сильная следующая проверка потребовала бы ASR+word alignment. Бюджетный промежуточный вариант — два отдельных запроса `gpt-audio-1.5` с EN N05/N06 только на короткую транскрипцию, maxoutput200; ориентир дополнительных расходов порядка$0.01–0.02, с отдельным резервом и PM-review. Число распознанных слов/длительность даст лишь apparent WPM; даже такой ASR не предоставляет проверенное word alignment и зависит от пропусков/ошибок. Reference разрешён только для последующей offline WER/wordcount-проверки; он не станет независимой метрикой judge. Этот вариант не авторизуется данным планом и не будет запускаться автоматически.

### Заранее определённые правила сравнения, сохранённые без изменения

V3 A/B оба были описаны чистыми; C дал частичную паузу7–9 s; fast D — ровный без скорости. В V4 шум отмечен во всех шести, длинная вставка названа короткой, N05/N06 оба moderate/steady, четыре ответа без pace.description. Эти baseline-ответы сохранены отдельно для сравнения, не передаются V5.

Для каждого ID будут сохранены raw response/usage и проверка схемы. Сравнение по тем же waveform:
1. Пауза: обнаружение увеличенного разрыва, границы/длительность и источник evidence. Ошибки/IoU против вставки и общего quiet отдельно. Правильное копирование метрик не засчитывается как независимое слушание.
2. Темп: порядковая модельная rate-категория и конкретное описание; отдельно отношение DSP-proxy. Нельзя требовать универсального «слишком быстро» без калибровки языка.
3. Шум: perception, описание силы/характера, impact отдельно; один `present` без отличия от original не считается доказательством селективности.
4. Оригиналы: новые заявления о длинных паузах, быстром темпе, шуме и дикции. Published clean означает отсутствие добавленного шума набора, а не абсолютную тишину; unsupported alert не автоматически доказанный false positive.
5. Схема/unknown/fallback и смежные ошибки сообщаются наряду с положительными результатами. Общая accuracy, статистическая значимость и причинное улучшение именно DSP не вычисляются.

Дизайн уже знаком с тремя парами и прежними неудачами; это exploratory follow-up, не независимый holdout. Одна попытка на файл не оценивает вариативность. Prompt и наличие metrics изменяются вместе. Разделены программная корректность, модельное мнение и известное преобразование; независимой экспертной разметки дикции/естественных дефектов нет.
