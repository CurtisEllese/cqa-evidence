# GPT-аудио: дикция RU / KZ / EN — ограниченный эксперимент

Дата: **8 ноября 2026, Asia/Qyzylorda**, запросы 02:32–02:35 местного времени. В raw и ledger время UTC: 7 ноября 21:32–21:35. Исполнитель: отдельная экспериментальная задача; PM выполнил независимую структурную и бюджетную проверку.

**Вердикт: pilot-only для исследовательских подсказок. Текущий подход непригоден для автоматических штрафов и итоговых баллов за дикцию.** Технически аудиовход и текстовый JSON работают на трёх языковых примерах, но обнаружены расхождение казахской цитаты с reference и вероятное принятие края обрезанного английского клипа за дефект речи. Три примера не доказывают точность модели или пригодность для операторских звонков.

Выполнено **ровно 3 платных запроса, без повторов**, модель всех ответов `gpt-audio-1.5`. Учтённый по фактическому usage расход **$0.03088**, сумма всех предварительных резервов **$0.282**, разрешённый cap **$0.30**. Luna не вызывалась. В продукт ничего не подключалось.

## Объём и изменение источников

Исходная задача предполагала три собственных операторских фрагмента. В кэше организатора 65 записей, из них только пять с аудио: `p4-ru-001`, `p4-ru-002`, `p4-ru-003`, `p4-ru-004`, `p4-ru-005`. Просмотрены их операторские транскрипты: подходящая речь KZ/EN не обнаружена. Все пять имеют RU label, но вывод основан также на содержимом реплик. Казахский текст служебного события и вступление бота не использованы как операторская речь. Поиск символов/латиницы — только вспомогательный screen, не акустическое определение языка. Это не доказательство отсутствия любого переключения языка во всём аудио.

PM сначала явно разрешил не блокировать RU-запрос из-за отсутствия KZ/EN. Затем передал согласие пользователя **«Да, открытые записи KZ/EN»**, с прежним совокупным лимитом. Поэтому окончательный набор состоит из одного собственного звонка и двух открытых реальных записей чтения. **KZ/EN не являются разговорами операторов; для них `domain_shift=true`.** Синтез, TTS, чужие закрытые звонки, монтаж нескольких записей и изменение скорости не применялись.

## Что проверено и что не проверено

Raw ответы сохранены отдельно от parsed ответов, quote checks и этой интерпретации. Локальный валидатор проверил поля language/speakers, confidence в [0,1], шесть разных dimensions, status, evidence, непустые evidence для observed, типы строк и `0 <= start < end <= 12`. Все **18 наблюдений / 18 evidence-интервалов** структурно допустимы. Это не подтверждает точность указанных секунд.

RU: цитаты «к сожалению мы не», «вам пока нужно», «самостоятельно» присутствуют в reference. Опорные события транскрипта лежат около 149.65 и 156.29 секунды относительно начала событий, а выбранное media — 134–146 s. В записи были pause/resume; исходное media длится 312.26 s, последние transcript events — около 320.21 s. Нельзя считать их прямой общей шкалой. Цитаты поддерживают выбор русского операторского контекста, но не доказывают изоляцию роли или точное акустическое выравнивание.

KZ: первая цитата также меняет `комитетінің` на `комитетін` и использует латинскую `A` в начале `AҚШ`. Нормализация регистра/пунктуации без подмены букв и без разрешения частичных слов даёт 0/2 совпадений. Это screen для проверки reference, не WER и не оценка произношения. Полный опубликованный текст сохранён в `reference-kz.json`.

EN: полный опубликованный текст заканчивается `in the Galapagos.`. Клип обрезан на 12 s при исходной длительности 12.58 s. В отброшенных 9280 float samples RMS = 0.10642, peak = 0.99206; в последних 50 ms отправленного клипа RMS = 0.01043. Это доказывает наличие сигнала в удалённом хвосте, **не** локализует слово и не подтверждает речевую природу сигнала. Нарезка — явный confound; вывод модели о смазанности нельзя превращать в штраф. Источник и клип оставлены для сравнения в плеере.

**Ни человек-исполнитель, ни независимый мультимодальный инструмент эти три записи акустически не прослушивали.** Только исследуемая `gpt-audio-1.5` получила аудио. Чтение транскриптов, просмотр ответа модели, декодирование WAV, проверка энергии и browser metadata не являются прослушиванием. PM независимо проверил raw/clip hashes, структуру, расходы и цитаты, но также не заявлял независимую акустическую проверку. Самопроверка модели не считается ground truth.

Публикуемые транскрипты KZ/EN относятся ко всему исходному файлу, а не гарантированно к первым 12 секундам. `exact_clip_transcription=null` сохранён намеренно: точной независимо размеченной расшифровки обрезанных клипов нет. Raw transcript не отправлялся модели.

## API, prompt и предварительный бюджет

Проверены официальные [модель и цены gpt-audio-1.5](https://developers.openai.com/api/docs/models/gpt-audio-1.5), [аудио в Chat Completions](https://developers.openai.com/api/docs/guides/audio-chat-completions) и [параметры запроса](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create). Использован `POST https://api.openai.com/v1/chat/completions`, `input_audio` с base64 WAV, `modalities=["text"]`, `max_completion_tokens=1000`, `n=1`, `stream=false`, `store=false`. Генерация аудио не запрашивалась. Structured Outputs у этой модели не поддерживаются: JSON запрошен в тексте и проверен локально, без заявления о серверной гарантии схемы.

Один неизменный prompt для всех трёх запросов сохранён как `prompt.txt`, его SHA-256 — в `budget-plan.json` и request metadata. Он требует шесть наблюдений: intelligibility, unclear_words, pace, pauses, intonation_variation, line_quality; evidence с локальными секундами/короткой цитатой или слышимым событием, confidence и limitation; допускает unassessable. Запрещает штрафовать акцент/шум, делать выводы о личности/эмоциях/намерениях, придумывать точные WPM/фонемные измерения/итоговый балл. Не сообщает ожидаемое качество или язык. Никакие паспортные, счётные или аутентификационные данные в prompt не добавлены; инструкция также запрещает выводить их в цитатах.

Тарифы на 1M токенов: input audio **$32**, input text **$2.50**, output text **$10**. Для каждого вызова до отправки записан резерв:

`2000 × 32 / 1e6 + 8000 × 2.50 / 1e6 + 1000 × 10 / 1e6 = $0.094`.

В [официальном описании расходов Realtime](https://developers.openai.com/api/docs/guides/voice-latency-cost?voice-api=realtime) указано 1 input audio token / 100 ms и наличие служебных токенов. Это даёт ориентир 120 токенов на 12 s. **Строгой верхней границы токенизации именно Chat Completions gpt-audio-1.5 не найдено.** Резерв 2000 аудиотокенов — консервативное допущение (16.67× ориентира), а не гарантия биллинга. Текстовый резерв 8000 покрывает короткий фиксированный prompt с большим запасом на обрамление; output ограничен параметром API. Полученные фактические audio tokens оказались 120 во всех трёх запросах; это наблюдение, не универсальная гарантия.

План сохранён до первого модельного запроса. Отдельный ledger обновлялся durable-write до network send. `max_retries=0`: HTTP transport без повторов; request один на язык; исключены fallback модели и повторная отправка неизвестно завершившихся запросов. При timeout, отсутствии breakdown usage или неожиданной модели сохранялся бы полный резерв и последующие запросы блокировались бы. Такие случаи фактически не возникли. Модельные raw ошибки отсутствуют, поскольку все три вызова вернули 200.
