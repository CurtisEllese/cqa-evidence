## Область и границы

Цель — проверить четыре параллельных изменения: player/date, durable server batch, eval/knowledge/audio и corporate auth/Dynamics. Этот документ не является заключением о готовности продукта. Исходники меняются другими исполнителями; все найденные ниже ограничения относятся к прочитанному снимку и требуют повторной проверки после их отчётов.

Обязательные ограничения задания: сохранить согласованную чистку интерфейса; **не менять, не скрывать и не сворачивать блок одиночной переоценки**; не проводить общий редизайн. Только `gpt-6-luna` в продукте. В этой работе нет платных/живых вызовов модели, обращения к организатору, публикации, Telegram, изменения кода, рабочей SQLite, `.env.local`, результатов DEV или Git-состояния. Создан только этот отчёт. `AGENTS.md` поиском в проекте и проверкой родительских каталогов не найден.

Разделять два допуска:

- **Конкурсный локальный показ:** официальный документ допускает показ без регистрации и входа; deployment необязателен. Отсутствие корпоративного входа само по себе не означает нарушение конкурсного ТЗ.
- **Коммерческий режим:** обязательны проверенная идентичность, серверные права, владение данными, сохранная очередь и честные ограничения AI. Нельзя называть локальную демонстрацию готовой корпоративной системой без этих доказательств.

Основной источник требований — [полный обзор Telegram](../telegram-full-review-2026-11-08.md), с его собственным отсечением 01:02:37 Asia/Qyzylorda. Новые сообщения и оригиналы вложений в этом QA-проходе не перепроверялись. Внешние материалы использованы только как источники требований.

## Как выполнять следующий проход без затрат и риска данным

1. Получить через PM итоговые отчёты и перечень изменённых файлов четырёх потоков. Прочитать diff и актуальные auth/batch contracts; зафиксировать хеши. Не применять checkout/reset и не править чужие файлы.
2. Создать отдельный временный каталог QA. Явно передать `database_path` на новую SQLite и `cache_path` на отсутствующий/синтетический файл, `organizer_url=""`, evaluator stub. Запускать отдельные порты, не перезапускать рабочий сервер :8000. При subprocess передать безопасные overrides; `.env.local` не менять и ключи не печатать.
3. Запретить внешний HTTP на уровне тестового harness и использовать локальные media fixtures. Явно изолировать budget ledger и knowledge fixture. Простого пустого `EVALUATOR_ADAPTER` недостаточно для доказательства отсутствия всех сетевых обращений: `create_app` загружает `.env.local`, а `/api/state` может инициировать refresh при пустой базе. Нужны explicit organizer/cache overrides и network guard.
4. Перед исполнением существующих browser/live scripts проверить side effects. `tests/browser_smoke.py` создаёт temp DB и пустой adapter, но запускает `backend.main` с наследуемым окружением и по умолчанию может прочитать organizer cache/настройки; для этой задачи не запускать его вслепую как «безопасный smoke».
5. Сначала A/Q/E backend negative tests с mock call counter; затем UI reconnaissance → дождаться загрузки → DOM/screenshots → действия по найденным селекторам. Webapp-testing применить в отдельном Playwright context с offline fixtures; никаких кнопок оценки на рабочем сервере.
6. После стабилизации выполнить соответствующие контрактные/unit проверки, TypeScript/build в согласованном изолированном месте и сквозной R01–R03. Не перезаписывать общий `dist`, если PM показывает его другим участникам. Новый общий test count не заменяет отдельные доказательства critical-path.
7. Для каждого FAIL записать воспроизведение, влияние и минимальный ожидаемый результат; задачи исполнителям назначает PM. Исправления в этом QA-чате не делать. После исправления повторить только затронутые и связанные критические сценарии.

Выходной gate: все применимые P0/P1 PASS либо явно согласованное PM ограничение **без заявления о прохождении**; неизвестные исходы/права/стоимость не допускаются как скрытые исключения. Для реальной Dynamics-среды и семантической точности допускается вердикт «не проверено» с узкой формулировкой готовности прототипа. Новые API-расходы требуют отдельного задания; текущие ~$0.095 и потолок $0.50 не являются разрешением на тестовый расход.
